## 定位与目标用户

agent-monitor 是面向个人开发者的 Claude Code / Codex 使用监控工具，以 CLI 和 Web 控制台提供用量、估算成本、会话归因、账号配额、多机采集状态及网络诊断。核心价值是帮助使用者回答：用了多少、哪些会话产生用量、哪个账号还有配额、所看的机器数据是否新鲜。它可在本机运行，也可通过 SSH 汇聚声明的机器；不是团队预算治理平台或 API 调用账本。

主要用户是频繁使用 Claude Code / Codex、跨模型或账号工作的开发者，以及维护个人多机 AI 开发环境的工程师。两者可为同一人：前者复盘使用，后者接入机器、维护采集并辨别失败。当前信任边界是个人可信网络；没有应用级身份认证，能够访问服务的人可操作保存的账号登录态。

## 场景、用户任务与成功结果

以下“成功结果”说明用户应能得到什么，不声明本次已验收通过；具体可判条件仍由现有 UX 契约维护。

| 场景与用户任务 | 有用的结果 | 所需能力与当前边界 |
| --- | --- | --- |
| 开发者复盘今天、本周或一段时间的使用 | 看清 token、估算费用与趋势，理解费用覆盖范围，避免把估算当账单 | Overview 与 Explore 提供统计、筛选、分组和等长周期比较；仅汇总可知的用量与成本，未计价原因可从采集与诊断追查 |
| 开发者追查某模型、机器或会话目录的用量 | 从聚合归因进入匹配会话，再查看与列表相同范围的会话用量，按需切换全部留存记录 | Explore → Sessions 钻取、日期筛选与详情；会话详情覆盖范围可能小于聚合历史 |
| 多机使用者查看整体活动，维护者判断采集是否正常 | 同时知道哪些声明机器贡献了数据、观测时间、失败与离线历史，而不是只看到一个合计 | 采集与诊断页集中机器状态和历史质量，业务页保留覆盖/时效限定与上下文入口；本地采集、SSH 快照汇聚和历史保留，离线时区分旧观测与新结果 |
| 使用者决定下一步使用哪个账号 | 区分账号身份、当前与历史记录，读到 5h/7d 配额、重置时刻及观测年龄；查询失败不会伪装成新读数 | 配额筛选、排序和刷新；显示账号身份、观测时刻与查询失败，配额记录不保证账号当前可用 |
| 使用者显式操作 Codex 单账号或一批账号 | 知道授权、发送和查询各自的结果，能够恢复未发送成员且不重复成功或不确定的发送 | 设备授权、固定短消息、仅刷新配额、批次恢复与结果保存；发送会消耗用量，成功或结果不确定的发送不自动重试 |
| 维护者排查网络或接入方式 | 看到服务所在机器的网络诊断，理解来源、安装和采集前提，找到正确命令 | Web / CLI 共用网络报告及使用与接入说明；诊断对象为服务所在机器，不是浏览器设备 |

## 会话应对齐用户使用体验

2026-10-19 用户批准：主会话及有明确来源父关系的 Codex 原生子代理呈现为一条会话，可含多个轮次；主视图保留标题或目录、机器/Agent、最近用量、记录费用与 token。优先使用来源已有标题，不采集对话正文或生成摘要。模型、用量事件数、观测跨度与执行 ID 保留在展开内容。独立启动的 wrapper、普通 fork 以及缺失或冲突父关系不靠时间或目录猜测合并，原始用量不删减。创建时间只能来自源元数据，最近用量不能推断运行或结束状态。

## 产品边界与解释约束

| 产品域 | 已记录边界 |
| --- | --- |
| 用量与成本 | 读取 Claude Code / Codex 留存来源；金额为记录金额或适用费率估算，不是订阅扣款或发票。未知不能当零，主视图说明费用仅合计可计价记录，分类数量与原因集中于采集与诊断；会话保留记录与聚合历史不保证完全对齐。完整口径由 [metrics](references/metrics.md) 维护 |
| 归因与时间 | “会话目录”按会话启动目录及 Git 身份归类，不拆分其后跨仓工作。用量聚合日界固定 Asia/Shanghai；显示时刻按 UX 契约处理。默认列表与详情使用相同筛选范围；切换全部留存记录后明确显示范围变化 |
| 历史与新鲜度 | 离线或查询失败可保留上一可信观测；保留不代表当前。未采集、无法恢复或来源不完整的历史不补造。历史记录中的部署、测试与性能读数不代表现在仍成立 |
| 配额与账号操作 | 配额是 provider 上报的账号观测；重置时刻已过不等于新读数。设备授权、发送和查询均需显式操作；发送会消耗订阅用量，不保证重置周期变化。成功或不确定发送不自动重试；无定时发送承诺 |
| 多机与安装 | 当前产品支持声明机器集合，本机与 Hub 模式依配置工作；现有机名是个人部署配置，不是所有用户必须采用的产品范围。采集失败、来源身份与数据时间需可辨识。状态与已保留历史在普通安装迁移中应保留 |
| 相邻产品 | agent-monitor 不采集 Gateway 调用，不拥有 API 请求/attempt 账本、路由诊断或 Gateway 控制台；这些由独立 llm-gateway 拥有。两者运行互不依赖，无共享数据库或 Gateway 导航承诺 |
| 组织能力与访问控制 | 个人控制台是现有定位；组织权限、团队预算执行及企业治理不在已记录能力内。可信个人网络之外的使用不在现有安全边界内 |
| 平台与开放准备 | macOS 支持 launchd，Linux 的调度安装跳过另有说明。开源准备不等于已可公开分发：许可证、发布历史范围和干净采纳者安装尚未在准备记录中完成 |
