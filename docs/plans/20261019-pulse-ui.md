## Reference and proposed design decision

2026-10-19 authenticated Pulse observation reached `/`, `/dashboard/` and `/pages/` in Chrome 157 at 1706×859 CSS pixels. Screenshots are in the evidence directory. Feed computed styles: `#f4f5f6` canvas, white sidebar and cards, `#1f2328` ink, `#59636e` secondary text, `#e2e4e7` border, system 14/21px text, 24/30px bold page title, 6px card corners, 180px white sidebar and 22px/28px main top/horizontal padding. Dashboard uses open summary metrics, 24px card padding, blue charts and sectional whitespace. These are current observed values, not inferred solely from CSS. Dashboard daily-table disclosure was inspected open; an individually authored report uses a separate green editorial presentation and is not the workspace design source.

Accepted decision (independent review passed): consolidate brand, area switch, search and navigation in a single white desktop sidebar; put the main content directly on the neutral canvas with white, thin-border section cards, open numeric summaries, stronger page headings and restrained blue actions. Retain all console/guide destinations, exact route/query return semantics, page search, existing chart category meanings and account-operation affordances. Use a slightly wider rail when needed for Monitor labels; narrow screens have a compact sticky header and scrollable navigation rather than compressed desktop columns. Adopt a shared visual system, not Pulse's business timeline or narrow article width for dense tables. Modify the authoritative existing styles in place rather than appending a competing theme. Reference-derived values and Monitor-specific adaptations are recorded in `docs/design.md`.

Alternatives considered: returning to GitHub/AI RADAR would re-decide the combination the user already prefers; building a new shared template first adds a separate unproven deliverable; retaining the Ark shell with recoloring would not satisfy the authorized complete visual/layout redesign. A single shared CSS/shell implementation is reversible through Git and uses existing native HTML/JS. Existing design decisions and historical observations live in `docs/design.md`, the UX contract and prior UI review records. The user explicitly supersedes their Ark appearance; known/unknown cost, observations, account safety, full-width data reading and preserved navigation remain constraints. No claim of improved runtime performance or exact source/production identity has yet been made.
