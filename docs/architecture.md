# Architecture

agent-monitor collects local agent usage and publishes read-only machine snapshots for a Web dashboard. It is an independent repository; ai-agent-config may invoke its installer but supplies no implementation at runtime.

The [upstream contract audit](references/upstream-contracts.md) records versioned arguments and original counterexamples. The [current repair arguments](references/upstream-contract-repairs.md) own the ten-object implementation mapping, conditions and unresolved source facts for account operations, credential identity, snapshots, isolation and process lifecycle. Source review is separate from deployment verification.

## Backend performance checks

Development follows the user-scope performance workflow for affected paths; explicit optimization starts by discovering consumers and representative states. Project evidence and commands live in [proactive-performance.md](proactive-performance.md). No deployment-wide latency SLA is implied by synthetic timings.

| Consumer / stage | Cost and lifetime to inspect | Existing evidence / regression |
| --- | --- | --- |
| Overview, Explore pivot/filters, sync status | `server` → `QueryView.snapshot` → admitted daily aggregates; per-request signatures grow with machine count, aggregate work with selected daily rows, not snapshot payload bytes | `test_query_view`: four consumers, repeated reads and generation change; `benchmark_backend.py`: row count and snapshot volume independently varied |
| View preparation | `QueryView.refresh` → admission → digest/schema validation; paid at startup and a new generation, retains old leased view while preparing | Application-cold/hot phases and new-generation preparation in benchmark; paused preparation and invalidation in `test_query_view` |
| Snapshot publication / GC | Copy and retained-history validation grow with snapshot/history size; their long work must remain outside the shared GC lock | Frozen copy at two volumes, retention check and cold validation in `test_snapshot_contention` |
| Full-history sessions | Session readers select retained agent events from leased generations; work grows with matching usage | Session/detail and statistics-snapshot tests; aggregate-view measurements do not cover these routes |
| Sync / quota / browser | Export, transport, publication, quota-only lifecycle, frontend status barrier and subsequent API fan-out have different costs | Existing sync/quota and Web tests; use the actual deployed page/API for latency claims |

Residual costs include cold/new-generation validation, session history admission/materialization and aggregate cardinality. Reassess the relevant row when changing its consumers; a completed Explore optimization does not close all rows. Synthetic padding only isolates digest volume; it does not model request-history retention, network or production distribution.

## Data flow and ownership

Snapshot preparation copies and validates under a preparation lease outside the machine GC lock. The short publication section rechecks the retained predecessor and retirement ledger, verifies the prepared file signature, and commits the existing journal/current/previous transition. Cleanup skips live preparations and reclaims abandoned ones. See the [prepared-view decision](adr/20261011-a8d3-prepared-query-view.md) and [performance evidence](explore-performance.md).

Claude Code and Codex logs enter through `parsers/`; `usage_archive.py` retains normalized events and `rollup.py` preserves daily totals and project identity through bounded rebuilds and shrink guards. Codex resolves physical thread ancestry at `history_base.end_byte_offset`, caching dependencies separately from parsing ancestor bodies. Claude selects a dominating observed usage snapshot per call, including retained archive observations, while retaining existing attribution. Incomparable observations and unresolved ancestry use existing `source_errors`/`scan_complete`; later known Codex deltas remain usable. State lives under `state/`, optionally a deployment-owned symlink. Source identities and persistent locks survive source-directory changes.

`exporter.py` writes versioned snapshots only from a committed, clean runtime. `statistics_snapshot.py` validates their schema and retained agent-event projections. `sync.py` asks declared SSH sources to run `~/.local/bin/agent-monitor export`; `generation.py` admits verified immutable generations, with leases and digests. Remote credentials and raw account secrets stay on their owner machines.

`hub.py` configures local roles and macOS lifecycle: every participating Mac collects locally, while MacStudio's Hub pulls admitted snapshots and serves the dashboard. Statistics collection stays at 120 seconds in Hub mode and quotas at 3600 seconds. Explicit refresh runs quota-only queries independently through `quota_sync.py`; its supervised worker streams machine results into the private `state/machine_quota.json` cache without exporting or publishing statistics. The GUI collector serves quota requests concurrently with rollup. Automatic schedules stay unchanged.

Hub synchronization runs each existing `sync_all` round in a fresh Python process through `sync_process.py`. The process owns export/publication allocations and generation leases, returning only statistics progress, machine outcomes and an explicit final result. The HTTP parent keeps refresh counters, queued rounds and account-memory/deletion coordination. `query_view.py` prepares each aggregate admission before HTTP consumption: startup initializes a leased view, one background lane refreshes it, and completion callbacks publish the view before progress becomes terminal. Overview, Explore and sync status share the prepared view; request-side configuration and file-signature checks fail visibly rather than falling back to full validation. Views keep generation leases until their last reader exits. Daily aggregate SQL and accounting remain in `rollup.py`; session history retains its own admitted reads. A control pipe identifies parent lifetime across same-PID reexec; explicit shutdown terminates and reaps the worker's local process group, excluding quota children that already create their own session. Protocol failure or missing final results enters the existing sync failure path. Standalone synchronization retains its existing in-process path. The independent quota cache overlays only matching admitted source, SSH target and provider/account identities; statistics retain membership and plan authority. One shared merged view serves overview, account directory, deletion checks and account memory. New observations retain their provider timestamps and failures preserve old values. Quota revisions trigger progressive rendering without a new statistics generation. See the [independent quota decision](adr/20261011-64e1-independent-quota-refresh.md). See the [isolation decision](adr/20261008-c4e2-sync-process.md).

`server.py` and `aggregators.py` answer the existing usage, session, pivot, quota and network API routes. `web/` renders those APIs; the renamed `AgentMonitor` JavaScript namespace is internal to these pages. Network diagnostics share `ip_check/` with the secondary `ip-check` CLI.

The overview workflow apply Prompt Planet's `usage-observability-console`, `record-explorer` and `request-diagnostics` v2 with the shared `console` v1 design profile. The frontend preserves brand blue, independent account quotas, distinct cost windows and session drilldowns. Its three cost summaries and trend share one surface; only the third summary and trend follow the range selector. Attribution charts precede account operations, advanced filters disclose on demand with removable active selections, and request results/attempts precede snapshot evidence. The product-wide visual layer now serves Overview, Explore, Sessions and Network through shared `web/styles.css`; [design.md](design.md) records the fixed style version, project adaptations and observation boundaries. This is a markup/style adaptation with no template runtime dependency or shared component package. The [original reuse decision](adr/20261006-91da-overview-template-reuse.md) records the v1 starting point.

The on-demand `/api/cost-diagnostics` groups retained unpriced observations by machine, agent, model and stored reason; absent legacy reasons remain unrecorded. It uses admitted snapshots with a null-cost SQL predicate before decoding, then exact date and canonical project filtering. Standalone mode uses the existing Sessions read-only diagnostic loader, including source parsing and current-price estimation (potentially fetching prices); it does not persist usage and is not a stored-reason projection. The browser reads it on entry/manual action, independently of the inexpensive `/api/collection` polling. No persistent schema or collection schedule changes.

The unknown-cost handoff uses the existing rollup counters: `metric=unknown_cost` derives `entry_count - cost_known_count` within the current row traversal. Sessions accepts `cost_status=unknown`, filtering retained events with null cost before grouping; detail defaults to the same filter and offers an explicit all-retained scope. Known zero stays known. This adds no storage schema, provider call or background scan; aggregate and retained-detail coverage can differ. See [9e31](adr/20261015-9e31-product-ui-handoffs.md).

## Independent runtime boundary

Account RPC children remain owned by their manager through shutdown. Admission closes before cancellation; TERM and, if needed, KILL unblock protocol I/O, while each worker reaps its child and releases its profile lock. Same-PID reexec and SIGTERM both drain account work before sync shutdown. Incomplete cleanup prevents reexec. The CLI provides a ten-second grace period. See the [child-reaping decision](adr/20261011-a72c-child-process-reaping.md).

`agent-monitor`, lifecycle scripts and `install.sh` resolve this project's `.venv`; the installer creates it from `requirements.txt` and vendors browser assets under `web/vendor`. `lib/install-output.sh` is the small optional FD ledger emitter, not a loader for the former parent repository. Installers can stage with `--no-services` before service cutover.

`claude_oauth.py` owns the extracted read-only credential/date/HTTP helpers. File and keychain candidates are lazy, deduplicated and locally validated; profile/usage requests refuse redirects and carry tokens only as headers. `quota_refresh.py` bounds the complete provider child process. Statusline rendering, statusline cache persistence and model-specific statusline windows remain harness responsibilities.

Monitor has no Gateway runtime dependency. `statistics_snapshot.py` writes agent-only extension v4 with a separate session metadata table, alongside usage quality, service context and cost provenance. It reads strict legacy v1/v2/v3 records without rewriting them or assigning evidence they did not contain; retired Gateway payloads remain ignored while the outer digest binds the entire file. Automatic publication rejects older observation times as well as lost retained events; explicit recovery publication retains its separate contract. Existing files are not deleted by this transition. The Gateway page, routes, optional snapshot indexes and call-only query workers have been removed.

Gateway owns its inference ledger and audit UI. Its optional independent archive importer handles historical v1 snapshots as a one-time migration input, without importing Monitor code. Live cutover must preserve all sources and independent collection before removing the old deployed entry; see [product separation](product-boundary-separation.md) and [the decision](adr/20261012-b97e-product-boundary-separation.md).

Publication checks history retention against the prepared copy outside the machine GC lock while holding a lease on the previous generation. It rechecks the current pointer under the commit lock and repeats retention validation if another writer advanced it. Copying and digest verification run outside that lock under a preparation lease; the signature check and recoverable pointer switch remain inside it. Reader admission acquires its generation lease under the same lock, then validates a cold generation after releasing it; the lease protects validation and use from GC. Matching sender/bundle manifests share one complete import validation. These changes preserve validation and retention rules while shortening the time readers must wait for publication.

## Web workflow queries

The [metric specification](references/metrics.md) owns units, windows, source versions and derivation arguments; its [operations appendix](references/metrics-operations.md) covers maintenance and diagnostic counters. Known-cost projections carry priced/unpriced observation counts through the same aggregation as amounts; pricing coverage is separate from scan completeness, snapshot admission and retained history. Sessions sum known selected amounts with a visible partial-pricing qualifier; unknown-only remains null, and recorded historical amounts are not automatically current-price valuations. Quota whole-reading selection and network coverage preserve unknowns instead of deriving a zero or healthy state from missing evidence.

Overview adds `attribution_windows` from the same date windows used by its fixed charts. Only `compare=1` computes period comparison: two non-overlapping complete-day windows share the admitted generations, and usage rollup rows retain known/unknown cost counts instead of folding missing prices to zero. `token_cost.py` and snapshot accounting are unchanged.

`/api/sessions` retains its default list response. The UI requests `with_filters=1` for an envelope of `sessions` and time-scoped `filters`. Date and dimension matching precede grouping; filter choices come from the date-window events before dimension filtering. The UI no longer tests a session's representative first model to decide membership. Detail resolves root/member IDs from the full session catalog, then uses the existing session index and date/model predicates to read matching records; `scope=all` explicitly selects all retained members. Front-end pagination remains unchanged.

Hub lists reuse each source's completed rows and filter choices through `session_cache.py`, after normal request-side admission. The key binds the source path, admitted file signature, window and semantic query; source updates invalidate independently. Moving windows require an unchanged start/UTC end date, a nondecreasing end, and no future candidate in the original complete read. Fixed custom windows bind both endpoints. The process-local LRU retains at most eight JSON results and 16MiB encoded content, returns independent decoded objects and holds no leases. There is no TTL, background worker or delayed refresh. Misses retain full decoding/validation and original aggregation; directory normalization runs once per distinct source project, and adjacent identical metadata reuse successful validation only within a read. Scalar fields remain checked per event. Cold/new-generation cost still grows with matching events; the encoded-content limit is not an RSS limit. See [d8f4](adr/20261019-d8f4-sessions-result-reuse.md) and the [measurement record](plans/20261019-sessions-performance.md).

`/guide` uses the existing shell and sync-status reader without changing configuration. `/api/network` adds `checked_host` to successful, cached and failed reports. Quota ordering is local to display and uses the final observation overlay; account actions and machine snapshot identities remain unchanged.

## Preserved contracts

The [task-oriented action extension](adr/20261017-82cb-task-oriented-web-actions.md) adds optional `profile_ids` to `batch-start`: supplied members must be nonempty, unique and entirely eligible; omission retains the legacy all-eligible behavior. A one-account new round uses the same batch path. Before replacing a manifest, excluded members of its published round retain their operation in the existing `batch_result` slot under the profile lock; a retention failure publishes and dispatches nothing. Existing CAS, global-idle and definitely-unsent-only retry guards remain.

`codex_accounts.py` owns explicit, click-triggered Codex account actions through a dedicated app-server subprocess per active profile. `server.py` exposes same-origin account-action endpoints; `web/codex-accounts.js` renders state within the overview lifecycle. Private profile directories under `state/codex-accounts` contain managed credentials and the last operation, with a persistent per-profile file lock. Isolated HOME/config/work directories keep ordinary CLI credentials and project tools out of these operations. Only pending device authorization information and sanitized account/operation metadata reach the browser. No background weekly scheduler is installed.

Message status and quota observation are separate: an interrupted transmission stays unknown, a successful message survives a quota-query failure, and quota-only refresh sends no message. The server timestamp remains authoritative; action results do not rewrite collected quotas, snapshots or account history. See the [design and acceptance boundary](adr/20261007-c814-codex-account-actions.md).

The [quota display projection](adr/20261007-a62e-codex-quota-display.md) compares existing machine and Web action observations in the overview renderer using workspace plus email and observation time. It selects a whole reading, including unknown fields. Original machine records still drive membership, plan provenance and deletion CAS; a separate display value supplies usage, reset and freshness with query provenance available inside observation details. The [label placement revision](adr/20261018-6f21-quota-label-placement.md) keeps history membership in the machine column and distinguishes unknown identity from signed-out state. Operation loads update the table, and page teardown clears the projection. The [retention extension](adr/20261008-e92b-retain-codex-quota.md) adds optional `last_quota` to private profiles and their existing account API response. Successful pre-send, post-send and quota-only readings persist atomically with the operation; replacing a legacy operation first preserves its newest observation. Failed or cancelled operations retain the reading's original time. Both UI consumers include it alongside legacy operation/batch readings. Machine snapshot schemas and account memory remain unchanged. The [account recovery extension](adr/20261011-7c3a-account-round-recovery.md) uses a dedicated HTTP-only OpenAI provider alias within each isolated child. Optional `operation.failure` stores the failed stage, a controlled category and an optional integer HTTP status; upstream free text is discarded. A failed or unknown send may open one fresh owned app-server for identity verification and quota-only recovery, with 20-second initialization, identity and query bounds. It never reauthorizes or starts another turn, and does not replace the original send failure when recovery fails. Both current and retained batch `before`/`after` observations participate in whole-reading selection.

The [batch extension](adr/20261007-b923-codex-account-batches.md) adds a current `batch.json` manifest with fixed profile membership. The shared catalog lock serializes creation/CAS, retries and individual starts. All profiles are prepared before the manifest is published; only then are jobs dispatched. Each current operation holds its batch result until replacement, when the published batch's completed result moves atomically into that profile's `batch_result` slot. Quota refresh therefore cannot erase the message result. Stale creation requests return the current batch; only explicit retries dispatch definitely unsent members. GET recovers interrupted state under a reread profile lock without replay. A semaphore bounds checking/sending to eight operations; authorization waits release their slots. Restart does not resume queued work automatically.

The [authorization queue](adr/20261008-f7c1-codex-authorization-queue.md) gives interactive logins one separate lane within the Hub manager. `login_queued` is active for cancellation and restart recovery, but holds no check/send slot. A login rate limit advances an in-memory generation: older queued attempts stop before requesting codes, while new explicit retries and saved-logins remain usable. Known CLI 429 strings map to safe explanations; arbitrary upstream errors never reach the API. There is no automatic new-code retry or message replay.

The [known-account extension](adr/20261007-d2af-codex-known-accounts.md) reads admitted Codex metadata and account memory without a provider refresh or memory upsert. It materializes private profiles automatically by workspace and email. The current directory determines send eligibility; profiles retain credentials/results independently. Current manifest members absent from the directory remain visible but do not enter a new round or explicit retry. Discovery exposes invalid identity records and fails visibly on unreadable account history. Metadata never supplies or exports authentication tokens.

Extraction changes names, installation ownership and source paths. It does not change bucket timezone, snapshot schemas, host/account identity, retention or arithmetic. `token_cost.py` is byte-identical to its extraction source. The source commit and historical docs are recorded in the [extraction ADR](adr/20261004-a902-standalone-project.md).

The console shares the `style:volcengine-ark-console` visual layer recorded in [design.md](design.md) across Overview, Explore, Sessions and detail, Network, and Guide. Page-specific task structures and data contracts remain owned by Monitor. Project overrides retain brand blue, chart series colors and distinct cost windows. The persistent header switches console/guide areas and local navigation while SPA swaps replace only `main`; its console return URL is kept separately from ordinary range propagation. Page/help search filters static destinations in memory, and guide copy controls use the browser clipboard with an HTTP-compatible fallback. These components add no UI framework, data requests, polling or template runtime dependency. Ark source access is used to author the template; ordinary product use does not require it.

Large session-detail JSON responses negotiate gzip with accepting clients; other responses keep their existing transport. Compression preserves the complete record list and default identity response for clients that do not accept gzip. This addresses transfer volume, not snapshot query work.

## Session indexes and runtime observations

New statistics snapshots create SQLite expression indexes on the unchanged JSON timestamp date and session id. The existing date predicate, timezone widening, position ordering, full event validation and grouping remain authoritative; unindexed older snapshots continue to work. Narrow date/detail reads scale with matching events plus index lookup, while unrestricted history, matching-event decoding, session grouping and browser pagination still grow with retained activity. Index construction adds work and bytes at export, not at publication admission or HTTP request time.

`diagnostics.py` owns bounded process-local operation tracking and a five-second file observer, started/stopped by the HTTP server lifecycle. HTTP, snapshot event reads, view preparation, statistics workers and quota workers report separately. View preparation supplies source metadata without making diagnostics readers depend on business locks. The observer emits transitions and slow/error completion events, and exposes coverage loss and persistence failure. It neither retries nor cancels business work; update schedules and admission remain unchanged. See [operations](operations/services.md#runtime-performance-diagnostics), [decision](adr/20261013-b4d8-runtime-performance.md) and [measurements](performance-20261013.md).

Quota presentation separates identified account comparison from unattributed machine observations without changing snapshot identity or schema. The collection page (`/collection`) retains raw usage and observation/reset times independently of account filters; Overview retains applicable low-headroom evidence and a contextual diagnostic link. `/api/collection` reuses one admitted view and the existing `_sync_status` / `_live_rate_limits_from_admission` authorities, without invoking Overview cost pivots or launching collection. It uses the existing visible-page refresh lifecycle. See [9c42](adr/20261018-9c42-quota-object-membership.md).

Page ownership and source-context return behavior are recorded in [20261018 page task ownership](adr/20261018-page-task-ownership.md).

## Conversation identity

`session_identity.py` separates session identity from immutable usage facts. The collector takes owner IDs and native parent references from the first Codex `session_meta`, plus name/title, source creation time and directory from the existing safe thread-database snapshot reader. It does not use physical log filenames, inherited metadata, `forked_from_id` or history-base relationships for conversation grouping. Only explicit native thread-spawn ancestry groups executions. Claude and older sources remain independently readable.

`usage_archive.py` transactionally retains one `usage_sessions` row per agent/session; absent sources retain existing metadata, mutable titles update, and contradictory parent evidence becomes a conflict instead of last-writer-wins. Snapshot v4 publishes this catalog separately from `statistics_usage`; admission rejects loss of retained metadata or known ancestry. Deploy the compatible Hub reader before v4 exporters. After v4 publication, rollback must retain that reader or use a compatible forward fix. No extra historical price replay is required.

Each Sessions request builds the ancestry index from retained metadata before event filters. Invalid chains remain separate; grouping partitions facts without changing keys or arithmetic. List reads still materialize the date window, while detail queries bind member IDs through `json_each` and the existing session index. The metadata cost scales with session count, separately from matching usage decoding. See [metrics](references/metrics.md#sessions), [decision](adr/20261019-c6b2-conversation-sessions.md) and [execution evidence](plans/20261019-conversation-sessions.md).
