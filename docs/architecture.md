# Architecture

agent-monitor collects local agent usage and publishes read-only machine snapshots for a Web dashboard. It is an independent repository; ai-agent-config may invoke its installer but supplies no implementation at runtime.

## Data flow and ownership

Claude Code and Codex logs enter through `parsers/`; `usage_archive.py` retains normalized events and `rollup.py` preserves daily totals and project identity through bounded rebuilds and shrink guards. State lives under `state/`, optionally a deployment-owned symlink. Source identities and persistent locks survive source-directory changes.

`exporter.py` writes versioned snapshots only from a committed, clean runtime. `statistics_snapshot.py` validates their schema and retained event/Gateway projections. `sync.py` asks declared SSH sources to run `~/.local/bin/agent-monitor export`; `generation.py` admits verified immutable generations, with leases and digests. Remote credentials and raw account secrets stay on their owner machines.

`hub.py` configures local roles and macOS lifecycle: every participating Mac collects locally, while MacStudio's Hub pulls admitted snapshots and serves the dashboard. Statistics collection stays at 120 seconds in Hub mode and quotas at 3600 seconds. Quota-only refresh follows statistics publication without a second statistics export.

Hub synchronization runs each existing `sync_all` round in a fresh Python process through `sync_process.py`. The process owns export/publication allocations and generation leases, returning only statistics progress, machine outcomes and an explicit final result. The HTTP parent keeps refresh counters, queued rounds and account-memory/deletion coordination. Its first admission of each new generation still performs cold validation: validation caches are process-local. A control pipe identifies parent lifetime across same-PID reexec; explicit shutdown terminates and reaps the worker's local process group, excluding quota children that already create their own session. Protocol failure or missing final results enters the existing sync failure path. Standalone synchronization retains its existing in-process path. See the [isolation decision](adr/20261008-c4e2-sync-process.md).

`server.py` and `aggregators.py` answer the existing usage, session, pivot, quota, network and Gateway API routes. `web/` renders those APIs; the renamed `AgentMonitor` JavaScript namespace is internal to these pages. Network diagnostics share `ip_check/` with the secondary `ip-check` CLI.

The overview and request workflow apply Prompt Planet's `usage-observability-console`, `record-explorer` and `request-diagnostics` v2 with the shared `console` v1 design profile. The frontend preserves brand blue, independent account quotas, distinct cost windows and requests-first loading. Its three cost summaries and trend share one surface; only the third summary and trend follow the range selector. Attribution charts precede account operations, advanced filters disclose on demand with removable active selections, and request results/attempts precede snapshot evidence. The scoped `.console-main` styles serve overview and calls without changing the adjacent Explore, Sessions or Network layouts. This is a markup/style adaptation with no template runtime dependency or shared component package. The [original reuse decision](adr/20261006-91da-overview-template-reuse.md) records the v1 starting point.

## Independent runtime boundary

`agent-monitor`, lifecycle scripts and `install.sh` resolve this project's `.venv`; the installer creates it from `requirements.txt` and vendors browser assets under `web/vendor`. `lib/install-output.sh` is the small optional FD ledger emitter, not a loader for the former parent repository. Installers can stage with `--no-services` before service cutover.

`claude_oauth.py` owns the extracted read-only credential/date/HTTP helpers. File and keychain candidates are lazy, deduplicated and locally validated; profile/usage requests refuse redirects and carry tokens only as headers. `quota_refresh.py` bounds the complete provider child process. Statusline rendering, statusline cache persistence and model-specific statusline windows remain harness responsibilities.

The independent llm-gateway repository supplies its Python audit reader through `gateway_dependency.py`; the default checkout is `~/research/llm-gateway`, overridden by `LLM_GATEWAY_ROOT`. Gateway owns ledger schema fingerprints, pricing policy and inference credentials. This consumer retains versioned field mappings and unknown-field rejection. No Gateway service is started by this installer.

Statistics projections accept exact Gateway schema versions 3–10. Versions 9/10 use Gateway's schema validator rather than membership in its historical fingerprint dictionary; schema 10 also carries `usage_missing_reason` on attempts. Unknown versions and missing or extra projection fields remain rejected.

The calls page, request diagnostics and JSON export use that reader through read-only HTTP adapters. Hub adapters hold an admitted-generation lease throughout each read. Detail lookup carries machine and project identity; its complete child chain is independent of the list window. Export returns one selected record kind across all matching rows. Different HTTP observations can see different generations; their envelopes retain their own source times. UI teardown and selection guards prevent a late detail response from replacing a newer page or request. No new collection, ledger or indexing mechanism is introduced by this UI integration.

For Hub request details, the snapshot reader selects the matching request (or the parent of the selected attempt) in SQLite before decoding rows, then reads every child of that request. Metadata from all admitted sources is retained. Missing or ambiguous requests still reach the shared reader's existing checks. Export builds optional `am_detail_*` expression indexes for these lookups before binding the snapshot digest. Versioned tables and payloads are unchanged; old snapshots remain readable without indexes.

`call_list.py` serves the initial Hub request page through `/api/llm-call-list`: validate active selections against the range's option authority, select request candidates and complete child chains in SQLite, then reuse Gateway row/filter/cursor projection. Metadata still covers all admitted sources. Export builds the optional `am_list_request_time` index before digest binding. Coarse SQLite time buckets are refined by exact Python timestamps; unsupported SQLite timestamps join through a fallback, preserving pagination. Sparse attempt filters and large timestamp buckets can still require substantial reads. Full-range counts, summaries, costs and independent attempts are null until explicitly loaded; complete filter options are also explicit. A full analysis replaces the displayed observation, and subsequent lightweight refreshes retain it only while its sources, watermarks and window remain unchanged. Standalone retains the full reader and has no list speed claim. See the [request-first decision](adr/20261008-f43a-request-first-loading.md).

The four full-history Hub HTTP routes (calls, calls-page, call-filters and calls-export) execute through `query_process.py`, including JSON encoding. At most two query workers run concurrently; other full queries wait before admission. Detail and health bypass those slots. Workers share `sync_process.py` lifecycle supervision and hold their own generation leases. The parent checks status, byte length and successful exit before sending the encoded body; projection error status/body and HEAD semantics are preserved. Complete exports are still buffered as bytes in the parent. Standalone routes remain direct. See the [query isolation decision](adr/20261008-d102-query-process.md).

The initial list adapter batches complete timestamp buckets before loading child attempts. This avoids one full attempt-table scan per request when a source still uses an exporter without the optional child indexes; it does not truncate a bucket or the matching attempt chain. Old sources need no deployment or snapshot mutation for this compatibility path.

Publication checks history retention outside the machine GC lock while holding a lease on the previous generation. It rechecks the current pointer under the commit lock and repeats retention validation if another writer advanced it. Copying, digest verification and the existing recoverable pointer switch remain inside that lock. Reader admission acquires its generation lease under the same lock, then validates a cold generation after releasing it; the lease protects validation and use from GC. Matching sender/bundle manifests share one complete import validation. These changes preserve validation and retention rules while shortening the time readers must wait for publication.

## Preserved contracts

`codex_accounts.py` owns explicit, click-triggered Codex account actions through a dedicated app-server subprocess per active profile. `server.py` exposes same-origin account-action endpoints; `web/codex-accounts.js` renders state within the overview lifecycle. Private profile directories under `state/codex-accounts` contain managed credentials and the last operation, with a persistent per-profile file lock. Isolated HOME/config/work directories keep ordinary CLI credentials and project tools out of these operations. Only pending device authorization information and sanitized account/operation metadata reach the browser. No background weekly scheduler is installed.

Message status and quota observation are separate: an interrupted transmission stays unknown, a successful message survives a quota-query failure, and quota-only refresh sends no message. The server timestamp remains authoritative; action results do not rewrite collected quotas, snapshots or account history. See the [design and acceptance boundary](adr/20261007-c814-codex-account-actions.md).

The [quota display projection](adr/20261007-a62e-codex-quota-display.md) compares existing machine and Web action observations in the overview renderer using workspace plus email and observation time. It selects a whole reading, including unknown fields. Original machine records still drive membership, plan provenance and deletion CAS; a separate display value supplies usage, reset and freshness with an explicit Web-query label. Operation loads update the table, and page teardown clears the projection. The [retention extension](adr/20261008-e92b-retain-codex-quota.md) adds optional `last_quota` to private profiles and their existing account API response. Successful post-send and quota-only readings persist atomically with the operation; replacing a legacy operation first preserves its newest observation. Failed or cancelled operations retain the reading's original time. Both UI consumers include it alongside legacy operation/batch readings. Machine snapshot schemas and account memory remain unchanged.

The [batch extension](adr/20261007-b923-codex-account-batches.md) adds a current `batch.json` manifest with fixed profile membership. The shared catalog lock serializes creation/CAS, retries and individual starts. All profiles are prepared before the manifest is published; only then are jobs dispatched. Each current operation holds its batch result until replacement, when the published batch's completed result moves atomically into that profile's `batch_result` slot. Quota refresh therefore cannot erase the message result. Stale creation requests return the current batch; only explicit retries dispatch definitely unsent members. GET recovers interrupted state under a reread profile lock without replay. A semaphore bounds checking/sending to eight operations; authorization waits release their slots. Restart does not resume queued work automatically.

The [authorization queue](adr/20261008-f7c1-codex-authorization-queue.md) gives interactive logins one separate lane within the Hub manager. `login_queued` is active for cancellation and restart recovery, but holds no check/send slot. A login rate limit advances an in-memory generation: older queued attempts stop before requesting codes, while new explicit retries and saved-logins remain usable. Known CLI 429 strings map to safe explanations; arbitrary upstream errors never reach the API. There is no automatic new-code retry or message replay.

The [known-account extension](adr/20261007-d2af-codex-known-accounts.md) reads admitted Codex metadata and account memory without a provider refresh or memory upsert. It materializes private profiles automatically by workspace and email. The current directory determines send eligibility; profiles retain credentials/results independently. Current manifest members absent from the directory remain visible but do not enter a new round or explicit retry. Discovery exposes invalid identity records and fails visibly on unreadable account history. Metadata never supplies or exports authentication tokens.

Extraction changes names, installation ownership and source paths. It does not change bucket timezone, snapshot schemas, host/account identity, retention or arithmetic. `token_cost.py` is byte-identical to its extraction source. The source commit and historical docs are recorded in the [extraction ADR](adr/20261004-a902-standalone-project.md).

The console application uses Prompt Planet `usage-observability-console`, `record-explorer`, and `request-diagnostics` v2 with console design profile v1. Project overrides retain brand blue, distinct cost windows, and on-demand full analysis/filter enumeration. Template rules guide layout and review; commercial-site access is not part of this application path.
