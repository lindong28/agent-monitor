# Upstream contracts: repaired implementation

2026-10-14. This is the current implementation companion to the [fixed-baseline audit](upstream-contracts.md). The audit retains its original counterexamples and dates; it is not the current repair status. Metric definitions remain in [metrics.md](metrics.md). The scope is the ten objects below, including their known failure cases. Passing a local test does not establish provider-final usage, invoice accuracy, arbitrary process-tree containment, or production deployment.

## Sources and maintenance

Claude private-format arguments use the inspected 2.1.296 binary, SHA256 `c9b5341637becbd423ddffc5b254afb645682a3868cb708bbc6cc0e7bb419937`. Private CLI persistence is a versioned producer implementation, not an API guarantee. Public pricing is the official 2026-10-14 snapshot; it is not a historical effective-price ledger. Fixed sources, offsets and original counterexamples are retained in `/Users/lindong/task-artifacts/upstream-contract-audit-20261014/`. Repair decisions, independent reviews and isolated results are in `/Users/lindong/task-artifacts/upstream-contract-repair-20261014/`.

When changing a producer version, find its corresponding emit/selection path before changing consumers. Recheck the affected row's premises and failure case, update this document and its metric definition, and retain old observations as dated evidence. Do not update a version number alone and inherit the old proof. For public API rules use the normative document; for private files use the actual producer; for product semantics use the accepted ADR. Tests check the implementation against those sources, rather than defining the source contract themselves.

## Evidence transport and consumer contract

The new `UsageEntry` fields are optional for legacy archive decoding. Statistics extension **v3** requires them explicitly and checks their shape and relationships; strict readers still accept original v1/v2 field sets without rewriting the files. Old non-null snapshot amounts keep unknown provenance instead of being relabelled recorded. Upgrade compatible readers before v3 writers; rollback must retain a compatible reader.

| Field | Values and meaning | Consumer |
| --- | --- | --- |
| `usage_quality` | `unknown`: producer marker absent; `incomplete`: explicit null marker; `observed`: nonempty stop marker. This classification applies to Claude observations. | Retained entries, v3 snapshots, session API and detail expansion. It is independent of source scan_complete. |
| `service_context` | null or bounded source facts `speed`, `inference_geo`, `service_tier`; missing key means unreported, explicit null means unsupported source value. Optional `conflicts` names inconsistent facts. | Mode pricing and per-entry evidence. Unknown explicit facts do not silently become standard service. |
| `cost_provenance` | null for legacy unknown, otherwise exact `basis`, `sources`, `verified_at`, `time_basis`, `reason`. Basis is recorded/nominal/unpriced; only nominal has valuation_time, all others unknown. Unpriced iff amount is null. Dates are actual source-verification dates or null. | Aggregator preserves the object; session API/UI shows the amount's basis, sources, mode and valuation scope. |
| `usage_quality_counts` | Exact observed/incomplete/unknown nonnegative counts over the snapshot's retained, deduplicated Claude records. v1/v2 = null, not zero. | Published Hub machine statistics; UI explicitly says all retained records, not the selected date range. Standalone/old snapshots without this metadata report unknown. |

Rollup keeps its existing amount and known/unknown coverage columns. It does not infer provider attempts or rebuild final usage from metadata. Overview, Explore and Sessions state the observed-use and requested-model scope. Sessions retain their strict unknown-total policy; mixed known/unknown entries are not silently presented as a complete cost. A scan with zero source_errors still does not prove final usage completeness.

## Runtime versions and bounded verification

The 2026-10-14 read-only runtime census found MacBook Python3.13.12/SQLite3.50.4, MacMini and MacStudio Python3.9.6/SQLite3.51.0, Tencent Python3.12.3/SQLite3.45.1. These SQLite versions are in the upstream [WAL-reset bug](https://www.sqlite.org/wal.html#the_wal_reset_bug) affected range. Project-owned writer/checkpoint/connection-close paths are serialized by the existing lock or operate on private unpublished copies; this excludes the audited cooperating write/checkpoint race. It does not prove external Codex writers safe or prove that corruption happened. No system Python replacement is implied.

Initial module verification: history 8 tests, snapshot/API 6, accounts 137, storage 203, runtime corrected 15; suites overlap and must not be summed. The consumer-related combined run passed 172 tests. State dimensions include three Claude quality values, four provenance states including legacy unknown, snapshot versions 1/2/3, two mode prices, multiple identity/bucket/configuration cases, and normal/death/deadline process states. These are finite input checks alongside the normative arguments, not an all-input proof. Final integrated, native-platform, browser and deployment receipts are recorded separately in the task execution evidence; pending receipts must not be inferred from these counts.

The final integrated run passed 981 tests. Native checks then exposed that MacMini's Python3.9 lacks `os.waitid`; the compatibility fix uses Darwin libc with the SDK's P_PID/WEXITED/WNOWAIT/WNOHANG constants, preserving observe-before-reap ownership. The added cases exercise live/nonblocking, exited/unreaped/reaped, inherited stdout and EINTR/error states. Native retesting passed 36 tests on MacMini; Tencent ran the same 36, passing 33 and skipping the three Darwin-only cases. These runs bind file hashes in `native-final-source.json`; they use isolated source/HOME and do not send provider requests. The compatibility delta was checked separately after the integrated run.

The isolated real-browser journey reads a synthetic v3 SQLite snapshot through the actual session API: three Claude quality states, four amount-basis states, two filter states and widths 1280/390. Four detail expansions, model filtering and retained machine counts were inspected. Narrow-screen inspection found evidence details scrolled out of view; their sticky bounded container was corrected and the journey repeated. This verifies these rendered cases, not arbitrary source logs or production totals. Production results remain a separate release receipt.
