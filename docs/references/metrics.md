# Accounting and parser contracts

These are maintenance boundaries for the current implementation, not provider billing guarantees. `parsers/` normalizes observed agent logs, `agent_monitor/ingestion/usage_archive.py` retains observations, `agent_monitor/accounting/rollup.py` maintains aggregates, and `token_cost.py` derives known-cost subtotals. Tests use synthetic observations; they do not establish live provider behavior.

## Usage and cost

Claude observations with the same response identity are deduplicated. A later usage vector may replace an earlier one only when no component decreases; incomparable vectors remain source errors rather than a componentwise invented maximum. Codex cumulative deltas require the previous counter at the inherited history boundary. Copied parent history does not count as child use, and current parent EOF is not a historical boundary. Missing ancestry, counters or models remain unknown; later independently known deltas can remain usable.

Known costs are subtotals over priceable observations. Known zero is distinct from unknown: costs `[2, 0, unknown]` have known subtotal 2 and one unknown observation; all-unknown does not become zero. Source scan completeness, price coverage, admitted machine coverage, retained date coverage and detailed-session retention are separate dimensions. Estimates are not invoices or reconstructed historical tariffs. Arithmetic changes to `token_cost.py` must preserve its shared contract and corresponding tests.

Aggregate authority is independent of session retention: `daily_usage_rollup` owns usage keys, with legacy project-derived fallback only for absent keys; project queries use `daily_rollup`. An identity blocker may prevent project attribution while independent usage totals remain available. Existing archive keys need explicit correction/replay when parser behavior changes; a parser fix alone does not repair already retained records. Date boundaries use Asia/Shanghai.

For nominal pricing, [pricing_fetcher.py](../../agent_monitor/accounting/pricing_fetcher.py) checks supported service-context values before applying rates. Its Claude Code path explicitly admits `inference_geo=not_available`; that sentinel does not name a region or authorize arbitrary future values. Unsupported context remains unpriced with `unsupported_service_context` provenance. Recorded costs follow the separate recorded-cost validation path.

## Account attribution and quota plans

[parsers/accounts.py](../../parsers/accounts.py) reads current local account metadata. In the default-home passive path, [quota_service.rate_limits](../../agent_monitor/quota/quota_service.py) pairs that metadata with a stored quota observation. The stamp does not prove which account produced an older observation after a sign-in change. Managed Codex homes instead supply their registry profile identity through `managed_codex_rate_limits`; their credential plan is read locally only when both the selected account ID and email match that registry identity. Missing or mismatched credential metadata remains unknown. A current row with neither raw plan source is marked `plan_verification=unverified` and the Web view shows **套餐未核实**. Cross-account session-link exclusions remain a separate safeguard described in [architecture](../public-architecture.md#usage-path). These quota identities must not be treated as retrospective usage or billing attribution.

`quota_service.rate_limit_block` publishes two independent facts: `reading_plan` comes from `RateLimits.plan`, carried with the quota event, while `credential_plan` comes from the supplied account metadata. Their clocks can differ. Retaining a newer cached quota observation preserves its reading plan while updating the independently collected credential plan, including an explicit unknown; an older exporter that omits the metadata key does not clear it. Query receipts use their attempt time against snapshot generation time to avoid replacing newer snapshot metadata. An elapsed reset does not create a fresh observation: the Codex parser retains the stored percentage and plan. A mismatch does not establish which source is stale, and one available source is not evidence that two sources agree.

[quota_view.plan_to_show](../../agent_monitor/quota/quota_view.py) derives the display value from the reading plan first, then the credential plan. It uses legacy `account_plan` only when both raw keys are absent; present-but-null keys do not permit that fallback. [web/quota.js](../../web/quota.js) uses the plan, percentages, source and time from the same selected account-action reading. A newer selected quota reading replaces the prior displayed plan on both upgrades and downgrades; older receipts cannot override it. The **套餐记录** cell, search and **配额更新** disclosure consume only that selected plan. Login metadata is a fallback when the reading has no plan, not a competing record or a mismatch warning. Its independent update time is not supplied and remains explicitly unknown. The original raw pair remains in the snapshot contract for compatibility; it is not rewritten into credential files. Independent authentication failures and account restrictions retain their own controls. [Account memory](../../agent_monitor/quota/account_memory.py) persists the derived `account_plan`, not the raw pair; remembered rows retain the existing historical details and expose both raw fields as null. Adding them to persisted records would require a separate schema change.

Codex names are provider-specific: `pro` → `Pro (More)`, `prolite` → `Pro`, `promax` → `Pro (Max)`, following [the pinned upstream definition](https://github.com/openai/codex/blob/e7f32cf1928a35a9232a633a51c2a03b5a7e2c72/codex-rs/protocol/src/auth.rs#L135). The Web row, search and retained machine/history displays share this mapping; other providers keep their own names. Unknown identifiers remain literal text, including object-prototype names. These labels do not establish dollar prices or current subscription rights. See the [original naming decision](../adr/20261105-655f2-quota-plan-sources.md) and [latest-record display rule](../adr/20261111-3b7f-latest-quota-plan.md).

Regression entrypoints are [test_account_identity.py](../../tests/test_account_identity.py), [test_codex_rate_limits.py](../../tests/test_codex_rate_limits.py), [test_overview_api_shape.py](../../tests/test_overview_api_shape.py) and [test_account_memory.py](../../tests/test_account_memory.py), using the [isolated development procedure](../../CONTRIBUTING.md#development-setup). They preserve the raw-source, missing-source, legacy-key and remembered-observation contracts with synthetic inputs. [test_web_static.py](../../tests/test_web_static.py) and [test_quota_explorer.py](../../tests/test_quota_explorer.py) cover the selected-plan display, replacement and search behavior; they do not verify a real provider account's current plan.

Earlier source comments cited `ADR-024` and `20260822-586a`, whose records are not included in this repository. This section records the current implementation and its regression boundaries, not a verification of those historical approvals or a new waiver of account-attribution risk.

## Account-read diagnostics

[codex_accounts.py](../../agent_monitor/accounts/codex_accounts.py) maps a fixed set of `account/read` error messages with JSON-RPC code `-32603` to bounded diagnostic reasons. Unrecognized messages keep the generic reason and a bounded redacted summary in `rpc_failure`. Known credential values from before and after the request are removed before syntax redaction and truncation; this is not a guarantee for arbitrary secret text. The summary persists with the operation, saved failure and pause, including post-send quota failures. The mapping explains a failed request; it does not decide admission, retry or recovery. [test_account_read_diagnostics.py](../../tests/test_account_read_diagnostics.py) covers this local mapping with synthetic responses.

The implementation records Codex 0.162.1 commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d` as its source pin. That existing pin is not a fresh upstream verification here. The former `20261023-b72e` ADR pointer has no included record; it is not required to find or maintain this implementation boundary.

## Project identity

Project aliases canonicalize stored paths consistently for pivot axes, filter values and filter matching. Equivalent-looking home-relative paths from different machines may share a row; this does not prove the directories contain the same work. Preserve the machine dimension so readers can separate them. Do not change canonicalization in one consumer without checking the others, or silently rewrite retained source identities. `tests/test_project_alias.py` covers the shared mapping.

## Codex paginated child baseline

`parsers/codex.py` permits an initial zero baseline only for a discrete source-verified version set, `history_mode=paginated`, `thread_source=subagent`, no `history_base`, and a settings checkpoint at the explicit `subagent_history_start_ordinal`. The relevant upstream chain filters parent TokenCount before seeding the child, records the boundary, and starts a fresh counter context. A later resume checkpoint, arbitrary ordinal or `total == last` does not establish zero. Never reset an existing counter.

Include repeated observations, unresolved ancestry, known-zero and unknown-price cases as relevant. Snapshot schema admission establishes identity/retention, not completeness of every provider call.

Quota is a timestamped account observation, not usage or a current permission to send. An elapsed reset timestamp does not prove recovery. Existing account applicability, pauses and uncertain-send outcomes survive restarts; do not clear them as part of an accounting change. ## Codex quota-only request contract

The same [`account/rateLimits/read` response](https://developers.openai.com/codex/app-server#auth-endpoints) may contain `rateLimitResetCredits`. `reset_credits.py` projects its authoritative `availableCount` into `reset_credits.available_count` and available detail rows into `credits`, retaining `expires_at` in Unix seconds. A null summary or invalid count is unknown, not zero. A null detail list means only the count is known, and a shorter list does not reduce the count. An explicit null expiry means no expiry; a missing or invalid expiry stays absent and displays as unknown. This optional field follows the selected quota observation through native/managed reads, quota snapshots, account-action results, synchronization and the dashboard. It is never joined with another observation's count or timestamps. Authentication renewal retains its existing `excludeResetCreditDetails` behavior. Reading/displaying these credits never calls the separate consume endpoint.

Pure quota queries use `codex_quota.read_bound` in both the account-action RPC and bounded native/discovered-profile reader. It checks the same local `(account_id, email)` before and after one `account/rateLimits/read`, rejects a missing or different response account and requires a usable five-hour or seven-day percentage. The credential home is the exact one passed to the child. Existing admission, cancellation, route bridge and pause ownership remain with each caller. Missing windows do not replace a previous valid reading.

The fixed upstream [account processor at e7f32cf](https://github.com/openai/codex/blob/e7f32cf1928a35a9232a633a51c2a03b5a7e2c72/codex-rs/app-server/src/request_processors/account_processor.rs#L1177) authenticates the quota method independently; its [rate-limit test](https://github.com/openai/codex/blob/e7f32cf1928a35a9232a633a51c2a03b5a7e2c72/codex-rs/app-server/tests/suite/v2/rate_limits.rs#L243) initializes then requests quota without `account/read`. That supports removing the extra identity RPC from pure quota queries. Login and sending retain it. This is not proof of an old `account/read` failure's root cause or that the installed binary equals this source pin. One quota RPC may include multiple upstream HTTP calls, including reset-credit metadata.

Unknown RPC errors retain protection and are not automatically replayed. `-32603` is an envelope, and an observed `401/token_revoked` response alone does not establish why it happened or authorize replacing credentials. Existing human-confirmed pause recovery is unchanged; successful quota reads do not authorize sending without the existing explicit provider permission conditions. See [the recurrence decision](../adr/20261106-quota-recurrence.md).
