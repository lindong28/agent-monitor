# Web 内容阅读体验审查（2026-10-15）

## 结论与范围

当前界面的主要阅读缺口是信息顺序与关联：读者通常需要先经过机器状态、口径说明和配置，才能看到要判断的数据；看到数字以后，又要跨区域拼接范围、数据新鲜度和失败原因。建议优先调整信息层级、就地状态与比较方式，沿用现有视觉系统；不要通过删除未知项、隐藏覆盖限制或把估值叫账单来缩短页面。

本次按产品定义中的用量复盘、配额判断、会话追溯、网络排查和接入任务，真实访问 `http://macstudio:39001`。观察时段为 2026-10-15 约 21:59–22:12（GMT+8）。范围是当时线上渲染内容；服务在观察期间报告 `ok=true, stale=true`，未将本轮页面绑定到固定部署 SHA，也未诊断该标记或重启服务。其他会话正在更新仓库，不沿用此前审查的部署身份。

这是整体页面审查，不是某个 diff 的回归归因。以下 R01–R12 均为本轮现场观察到的产品现状及建议，本轮未实施产品变更。

## 逐项发现与建议

### R01｜优先：会话页主内容出现太晚，机器说明重复占据首屏

会话列表第一条记录在桌面文档坐标约 1,189px，390px 窄屏约 1,782px。之前是 4 台机器的完整同步说明、新鲜度、筛选和多段边界解释。每台机器都重复结束标记、不完整、未知条数，以及“全部留存，非日期范围”“结束标记不保证最终 usage”等共同限定。使用与接入页也默认展开同类机器信息；总览和透视已有折叠摘要，可作为现成参考。

建议让列表顺序变为：标题与同步摘要 → 筛选 → 结果数量与一行范围说明 → 会话列表。摘要保留机器可读数、更新中和影响数据的异常；各机器明细放“采集详情”，共同口径只解释一次。“列表仅计筛选记录，详情含完整留存”的重复段落合并。100 条列表的分页入口在底部，建议顶部也提供，避免读者必须滚过整页才能换页。

改善判据：默认桌面首屏能看到首条会话；窄屏尽早看到筛选和结果。不能为了压缩而隐去缺采集或未知费用。

### R02｜优先：配额数值、登录有效性和新鲜度需要跨区域拼接

当前有在用 3 条、历史 8 条和身份未知机器 1 条。独立警告说明部分机器未登录或登录失效，但表内仍有 0% / 7% 等旧读数；有的已经 2 天或 4 天未更新。“在用”“登录态已保存”与“当前登录有效”不是同一件事，读者必须自己把警告、机器和账号行对应起来。

建议每行直接显示与该数值相关的状态，如“旧读数 · 登录失效”“身份待核实”，观测时间紧邻余量。历史来源、机器记录、本页查询及相同时间戳集中解释一次，完整溯源仍可展开。窄屏让 5h / 7d 窗口并排，压缩重复来源文字，保留每个值与账号、状态的关联。

改善判据：仅阅读一行就能区分当前观测、旧观测和身份不确定；无需先背下页首警告，也不把旧 0% 当作当前可用凭据的证明。

### R03｜优先：账号批次结果与下一轮参与范围没有就地解释

摘要显示“本轮发送成功 9/11”“下次重置已知 9/11”，展开后的按钮是“开始新一轮 · 全部 9 个账号”。失败详情说明有两个成员已不在当前登录目录，批次开始时间藏在帮助中。数字可以各自成立，但读者第一眼不知道为什么分母变化，也容易混淆发送结果与最新配额状态。

建议摘要同时交代批次身份和参与范围，例如“10 月 15 日 14:39 批次：9 成功、2 未发送；新一轮参与 9 个账号”，失败卡就地说明原因。账号卡先给消息结果、配额结果与观测时间，工作区 UUID、发送前后重置值等移入技术明细。保留开始新一轮的周期约束和发送含义，不把重发包装成处理所有失败的默认动作。

### R04｜优先：网络风险结论比证据更强，主要异常排在页面末尾

当前标题为“Claude 使用风险高”。实际页面有 IPv6 公网未核实、DNS 地域缺失，公网 IP 正常，时区异常；时区的本地 +08 与出口 America/Los_Angeles UTC−07 不一致命中本地规则。风险分是“未查询”。在窄屏，时区证据约在文档 2,120px，位于多块信息之后。

建议主结论改成有来源边界的描述：“本地检查命中 1 项：时区不一致；另 2 项未核实”。将命中项排在正常项前，可从摘要跳到证据；继续明确这是 macstudio 服务端环境。规则、阈值和限制保留在展开说明内。字段按真实状态区分“未查询”“未配置”“无数据”“不适用”，避免统一用“—”。

这不是对服务商封禁风险的实测，也不构成让用户改系统时区的建议。改善目标是让结论、规则和证据对应。

### R05｜次优先：总览存在多个时间范围，顶部筛选的作用域靠长说明维持

顶部 30 日筛选与今日、本周、近 30 日摘要、本周目录、本月模型、提供方 5h / 7d 配额同时出现。页面已有范围说明，但读者仍需记住哪些卡片跟着筛选变化。配额入口较靠下；390px 观察中“配额用量”标题约在 2,339px。

建议将“当前概况”与“所选区间分析”明确分区，各区域就地显示日期与时区；配额提供页内直达入口。周期比较实际显示最近完整 30 日与前 30 日，建议先用一句话说明差额和比较区间，再列精确数字。未知定价条数和覆盖量不一致时一并提示，不能把已知小计减少描述成真实账单节省。

### R06｜次优先：金额、精度和覆盖说明混排，削弱扫描比较

成本数据表每个金额格同时包含金额、已定价条数与未知定价条数，例如 `$17.7784 已知小计 · 已定价747条 · 未知定价712条`。整格右对齐并不能让其中金额纵向对齐；不同长度的尾部说明会移动数字位置。每行“未知 0 条”的重复信息与四位小数也抢占阅读注意力。周期比较 token 数显示十位以上整数，差额显示 `$-6,259.69`。

建议金额独立对齐，覆盖信息独立列或次行；默认金额精度按阅读场景简化，保留按需查看完整精度的路径。未知非零突出，已知为零不与未知混同。大型 token 数用易读单位并保留精确值。周期比较先显示方向和数量变化，符号格式一致。

### R07｜次优先：图表标签可读性与口径提示不够直接

窄屏目录图出现 `philo_…rawler`、`lindon…config` 一类难以辨认的标签；展开数据表可以读完整路径，是现有补救能力。“本月模型构成”没有在标题直接点明按 token 占比，展开表却给出大量精确 token 整数。

建议以可区分的短项目名为主标签，完整目录和归属为次级信息；不能仅取 basename 造成同名目录混淆。模型图直接叫“本月模型 token 占比”，图表和数据表保持一致标识；常用阅读用短数，追溯时看精确数。

### R08｜次优先：透视先要求配置，结果阅读与追查又过于冗长

桌面图表标题约在 609px；窄屏约 1,193px，排行约 1,559px。SELECT / WHERE / GROUP BY 虽有中文副标签，仍是技术词优先。目录筛选有 80 个实体选项，包含长临时路径。选择“Agent × 会话目录”后出现 105 个组合，逐项重复 Agent 类型、会话目录、覆盖说明和链接，比较成本不方便。悬浮排行会展开逐日长明细。

建议增加一句可读查询摘要，并把常用视图置于高级配置前：“近 30 天 · 全部机器 · 按模型比较已知成本”。中文任务标签优先，SQL 术语次要。目录使用可搜索选择器；多维排行用紧凑表格，拆开 Agent、目录、金额、未知条数，可排序与查找。逐日细节按需展开，不用每项重复解释公共口径。

未知成本视图实际有 11 个模型组，其中 6 个非零、5 个为零，零组仍显示“查看含未知成本的会话”。建议优先显示有待追查记录的 6 组，明确“另 5 组没有未知成本”，零组不提供会导向空结果的同名操作。自定义日期空输入已有明确提示，本轮不报它是缺陷。

### R09｜次优先：会话身份和异常原因隐藏在技术标识之后

列表以目录、模型、时间等识别会话，同一目录下重复项不易区分。详情的大标题是 UUID，目录、Agent 等上下文在“会话信息”中。读者点进来后要再展开确认是不是目标会话。Claude 两条记录相隔约 11 秒，跨度显示“0 分钟”。

建议目录或已有可用标题作为主要身份，开始时间、Agent 与模型就近呈现，UUID保留为次级可复制标识；不因此新增对话抓取。不到一分钟显示“少于 1 分钟”或秒数。

未知费用记录展开后，原因“服务模式无法定价”在最末，前面是消息 ID、日志 ID、服务模式原始 JSON 和价格字段。建议首行就给“费用未知：服务模式无法定价”，其次 usage 质量与定价依据，完整原始 ID / JSON / 时间锚放技术明细。Codex 的“不适用最终 usage”不要与 Claude 的未知质量状态混同。

### R10｜次优先：窄屏会话详情能显示，但仍不便于逐条阅读

390px 视口下，详情表约 760px 宽、内容容器约 282px，金额与“查看”入口在右侧，需要局部横滚；整页没有溢出不代表记录易读。上方四个 KPI 逐个堆叠，也推迟条目出现。

建议窄屏摘要用两列，减轻多层容器 padding；每条记录先展示时间、模型、成本，展开后看 token 细项与来源。若保留表格，至少固定识别列并明确横向滚动提示。相同日期与时区可在记录组统一标明，仍可查看完整时间，避免每行重复完整日期、模型和“名义估值”。

### R11｜次优先：接入帮助有信息，但任务路径与跳转不够直接

使用与接入把首次单机、多机、已有安装的身份保全混在同一组步骤中，多机 JSON 占较大篇幅。README 和 operations 以文件路径出现，读者不能直接在当前页面阅读所指内容。排障文字说“去总览展开……”但未充分利用直接入口。桌面左侧章节与右侧目录重复，窄屏横向章节后再出现本页目录。

建议将“首次单机”“添加多机”“已有安装维护”分成明确入口；代码块可复制，步骤结束说明预期成功标志，文档路径转成真实可达的帮助入口。保留账号和机器身份约束。窄屏数据来源表的“查看入口”位于横滚右侧；三行说明可改成卡片，让入口直接可见。目录保留一个足够的导航层。

### R12｜贯穿：说明应分成结论、解释、溯源三层

成本估值、已观测 usage、实际路由未知、结束标记不保证最终 usage 等限制都必要，目前多个页面、多个机器、多个记录重复完整表述。成本口径折叠内还有近 28 日重算、缺源保留、窗口外冻结等维护者信息。

建议每个任务就地保留一句决定读法的限制，展开解释“这会如何影响我的判断”，最深层再放实现与溯源。不能把关键限定全部塞进帮助页；账号失效、未知费用和覆盖不足必须仍与相关值同屏。此项与既有 ISSUE-UX-20260826-da8a 有关联，本轮不据此关闭或重判历史 issue。

## 值得保留的现有能力

- 全站导航与页面/帮助搜索可用；搜索明确不搜账号或会话，无匹配有说明，配额结果可直接到对应区域。
- 图表都有读取完整数据的路径；成本未知不直接归零，周期比较和会话钻取已经能连接复盘任务。
- 会话详情区分成本、token、条目、跨度，明确非账单、非请求数、非活跃时长。
- 网络页明确测的是服务所在机器，规则中保留“未检出不保证可用”的边界。
- 接入页的章节锚点和身份保全提示有价值；建议调整呈现层级，不推翻这些能力。
