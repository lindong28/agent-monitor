# Product visual design

This mutable record describes the shared visual layer and its observed application. Future pages inherit this layer; page-specific task layouts and business contracts remain in their existing owners.

## Effective design

The selected style is Prompt Planet `style:vercel-gateway-console` v1. The actual input for this application was the frozen local definition at `/Users/lindong/research/prompt-templates-webui-site-style-20261008/library/webui/versions/vercel-gateway-console/1.json`; its canonical version URL is https://prompts.aiplanet.live/api/webui/v1/templates/vercel-gateway-console/1.json. Commercial-site access was not used. Overview and LLM Calls retain the existing `usage-observability-console`, `record-explorer`, and `request-diagnostics` v2 structures; the product style overrides their visual defaults. Explore, Sessions and Network need no additional scenario template.

`web/styles.css` is the shared entry point for all five routes, including dynamically rendered details. New pages use the existing `.main`, `.page-title`, `.panel`, form, table and disclosure classes. There is no page opt-in class or template runtime dependency. Shared defaults are system sans-serif 14/22px text, 24/32px page titles, 16/24px section titles, 28/36px primary metrics, 12px supporting text, 36px controls, 8px corners, white surfaces, neutral canvas and light dividers. Normal panels have no elevation shadow. Navigation uses a neutral selected surface; the common Refresh action uses a dark fill. Tables use 12×16px cell padding and local scrolling.

Five default routes were rendered at 1440, 1152, 1024, 960, 720, 390 and 320 CSS pixels. The 1152/960 samples correspond to 125%/150% layout scaling of a 1440px viewport, not OS/browser chrome zoom. Overview and Network were additionally checked at 481, 800 and 801px; the affected 320/390px states were captured again after fixes. Final sampled page-level horizontal overflow was 0px. Wide tables retain local overflow. This is a finite sample, not all viewport widths or all data states.

Reading observations: Overview puts the three explicitly named cost windows above the trend; attribution is below the first panel and quotas require scrolling. Explore exposes metric/filter/grouping before chart and ranking. Sessions keeps fleet freshness before filters, so narrow screens require scrolling to reach rows; this existing task order is retained. Request details show result and attempts before routing/source evidence. Network leads with verdict and explains the recorded timezone mismatch in the conclusion card. Default views, populated/empty quota state, two distinct sessions and one request detail were sampled; the entire retained history was not read.

On the cache-only preview, observed metric change was 0.033–0.041s, session sorting 0.047–0.050s, detail entry 0.036–0.040s and detail return 0.041–0.042s in the final interaction run. These measurements used DOM `click()` / change dispatch and a following animation frame, not native pointer timing, production latency or controlled cold/warm benchmarks. The separate native click/select chain validated reachable controls and navigation results after scrolling targets into view; an offscreen click returning Done without navigation was not counted as success. Recorded LCP was 0.016–0.068s on default route samples and up to 0.488s after disclosures; LCP includes shell/text and does not establish asynchronous data availability. Target readiness was checked separately after browser navigation, but exact first-content readiness from navigation start was not instrumented. A no-action metric-change control timed out while native selection reached the total-token state. Overview repetition measurement found maximum repetition 2 and 3.0% redundant counted line characters (account labels); no pass threshold was declared.

Validation used the existing `tests/test_web_static.py` suite: 40 tests, with its existing quota, request, navigation and rendering cases; no backend suite or production account tests were claimed. The implementation review gate took the default no-external-review path: this diff changes CSS and two opt-in classes, has no new data/permission/timing semantics, and the observed layout failures were reproduced and checked in the browser. Decision scope was L0, a reversible implementation of the selected visual design; assurance was A0/V0 with existing tests and direct browser checks. Documentation synchronization was ordinary source/diff verification, without independent documentation review.
