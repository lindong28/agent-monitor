# Dashboard presentation

`web/styles.css` is shared by Overview, Explore, Sessions, Collection, Network and Guide. This guide preserves the implemented presentation boundaries without requiring the original template service or another project's UI at runtime.

Use the existing CSS tokens and components for typography, neutral surfaces, tables, disclosures and actions. The dashboard uses Chinese labels. Keep account identity, quota value, reset/observation time and available action associated in the same row or narrow-screen card. Put traceability in accessible details, while keeping limitations that change interpretation beside the affected result. Do not repeat a conclusion already clear from the value or group context.

Agent-only trends use stable colors: Claude Code blue `#2a78d6`, Codex orange `#eb6834`, independent of order/date/filter. Comparable rankings use the existing horizontal bar presentation with category, numeric scale and end value; do not replace these with ambiguous progress tracks. Preserve drill-through context between totals, filtered sessions and details.

Overview groups its three cost readings in one panel; only the selected-range reading and trend follow the range selector. Explore groups dates, presets, query summary and advanced controls, with shared result explanations for charts/rankings. Daily pages omit the machine-status box; current machine health and technical evidence belong on Collection. Manual-refresh receipts and cost-completeness qualifiers remain beside the relevant actions and values.

Keep navigation, page heading, filters and expanded content usable at narrow widths. A CSS change in a shared component affects every consumer, including expanded rows and error/empty states. Use the README sample to inspect actual session navigation, plus the existing Web tests, before claiming a UI change is usable. Screenshots or aggregate test counts alone do not establish the reading/task flow. Accounting, identity and provider-action semantics are defined by the backend, not by presentation changes.

Codex account actions keep batch observations and actionable restrictions beside the batch controls; sending rules and connection/authorization help have separate disclosures. Account detail triggers and adjacent actions retain their positions when expanded. Disclosure bodies use spacing and an inset neutral surface to show ownership and ending. The peer recovery-history and sending-rules bodies share the `supplementary-body` enclosure, including their border, radius and content inset. The embedded recovery panel uses that enclosure rather than drawing a second card; standalone quota recovery keeps its own card. Nested recovery diagnostics retain a distinct inner surface. Display identical current restriction and operation text only once. Retry remains subject to backend account restrictions; a clickable continuation control does not mean quota restrictions have cleared.

Within account details, show the current operation and quota observation before history, technical diagnostics and account management. Use visible section headings and spacing rather than additional nested disclosures; omit empty groups and retain all available diagnostic fields. Workspace and saved-login context stay with account management, while duplicate workspace identity remains beside the account heading where needed.

Accounts puts search, state filters and individual account actions first. Batch mode starts with an empty selection shared by query and send groups; selecting all applies to the current filtered result, and any selections outside that result are counted explicitly. Ending batch mode clears selection. Connection help and complete channel recovery stay below the list and open on request; a channel pause keeps a compact summary above the list. Local status rereads do not query a provider. Overview links to the exact managed profile and refresh task; navigation does not submit a provider action. Collection owns machine quota diagnostics and automatic-refresh configuration. The collected quota table and managed cards retain their distinct identity sets; navigation matches workspace ID and email. Current restrictions stay outside historical receipts. Normal plan-source explanation appears once, exceptional sources remain inline, and raw evidence stays in the existing observation disclosure. The sorting-window selector is conditional on a quota-dependent sort.
