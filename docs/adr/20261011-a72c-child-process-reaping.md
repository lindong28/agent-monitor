# Drain account children before restart

Accepted on 2026-10-11 after one independent decision review. The owner requested repair of observed zombie processes, local recovery and third-party detection. Scope is the local Agent Monitor lifecycle; no provider calls, remote deployment or publication are authorized by this decision.

Keep the existing same-PID reexec interface, but close account-work admission and cancel, terminate and reap its registered children before reexec. Retain sync/query supervision. SIGTERM must reach the same cleanup path; the CLI allows up to ten seconds, returning earlier when the server exits. Failed account cleanup prevents reexec. Preserve the existing unknown-send state and never replay interrupted messages. A real stop/start, after checking for active account work, recovers children already lost by earlier executions.

On 2026-10-11 the same seven Z-state children still belonged to server PID 51187 as in the preceding inspection. Source inspection found that reexec called only sync shutdown, account shutdown relied on atexit and a three-second join, SIGTERM was unhandled and CLI stop allowed only two seconds. These observations establish a lifecycle gap, not the individual creation path of those seven children. Verify normal completion, cancellation, restart during work, SIGTERM and failed cleanup using isolated real children before deployment.

A new supervisor or global waitpid collector would expand ownership and could consume another caller's exit status. Periodic process killing cannot reap an already-dead child and risks disrupting its parent. Completing the existing owners' cleanup is narrower. This extends the account-actions and sync-process ADRs without changing provider, snapshot or scheduling contracts. Existing unattended application-failure alerting remains tracked in the service operations TODO; this change adds no outbound channel. Rollback is a source rollback and controlled service restart, never a state restore or message replay.
