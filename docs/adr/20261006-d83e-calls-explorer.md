# Machine-aware call exploration and request diagnostics

Status: accepted for local implementation, 2026-10-06. One independent decision review and a targeted clarification passed; publication and deployment remain separate authorization steps.

Apply the Vercel Logs record-explorer and request-diagnostics pattern already used by Gateway to agent-monitor's calls page. Keep compact request-first summaries, a filter rail, the request table and one right-side diagnostics panel. Cost breakdown and the independent attempt audit table remain available through disclosures, with their original fields and pagination. Use a neutral work surface with the monitor's blue accent, and retain visible machine coverage and collection faults. This is a project adaptation, not an assertion of identical Vercel branding.

Add read-only request-detail and export endpoints as thin adapters to the independent Gateway audit reader. Each Hub response reads its own admitted generation snapshot; standalone mode uses the existing local reader. Detail identifies a request by machine, project and logical request ID and shows the complete attempt chain, including attempts outside the list's time window. Its own observation and source times remain visible; a later detail is not a frozen continuation of the list snapshot. JSON export selects requests or attempts and includes all matches, independent of page cursors.

Preserve H1–H8 identity, request-time/attempt-time filters, URL selections, independent pagination and cost semantics. Unknown is not zero, subscriptions do not acquire an invented per-call fee, and no request-level cost or TTFT is fabricated. Selection, close and page teardown invalidate pending detail responses; closing returns to the current list context. Collection frequency and backend performance mechanisms are outside this unit, as explicitly assigned by the owner to another session.

Cosmetic changes alone cannot provide diagnosis. Copying Gateway's server/index duplicates the reader and expands backend scope; opening Gateway separately loses the monitor's machine context. The existing multi-source audit interface provides the required read behavior without either change.
