# Follow selected identities and target quota buckets

Date: 2026-10-14. Status: independently reviewed and accepted; production operation is separately verified.

The user requested fixes for the versioned upstream audit. Codex 0.162.1 ordinary ChatGPT auth uses selected tokens.account_id, and resolves email from the top-level claim then the namespaced profile. Claude 2.1.296 selects metadata, secure-storage directory and Keychain service/account using configuration-specific rules. Existing Monitor readers differed on controlled conflict/custom-directory fixtures. Align these selectors, preserve workspace+email identity and verify credential ownership using the same token's profile before attributing quota. Do not rewrite historical identities or enumerate unrelated credential stores.

Choose the codex quota bucket explicitly. A present multi-bucket map without codex does not authorize fallback to another bucket; passive logs likewise ignore explicitly different limit IDs. Unreported legacy IDs follow the pinned producer's default only. Missing identities remain unverifiable, not an instruction to update the CLI without evidence.

Account-action isolation follows the pinned upstream temporary-thread mechanism: disable unnecessary external capabilities, enumerate effective MCP configuration, and verify returned permissions before sending. Preserve managed profiles and require their returned identity plus actual read-only permissions; incompatible or unverifiable configurations refuse the action. Private HOME does not eliminate system/managed configuration, and model-catalog internal tools mean this is not an absolute zero-tool guarantee. This preserves the bounded fixed-message and no-automatic-replay policy in the existing account ADRs.

Rejected alternatives include JWT-over-selected identity, arbitrary quota-bucket fallback, searching all credential stores, and bypassing managed configuration. Sources and counterexamples are in [upstream contracts](../references/upstream-contracts.md); the accepted nine-item packet and independent review are in `/Users/lindong/task-artifacts/upstream-contract-repair-20261014/accounts-decision*.md`. Real account occurrence rates, cross-organization OAuth accounting semantics and actual provider calls are not established by isolated validation.

Implementation review addendum, 2026-10-14: the fixed producer chooses active auth mode before reading stored tokens. A valid API-key file can retain old token fields; those fields do not make it ChatGPT auth. Follow explicit mode first, then the producer's non-null credential precedence when mode is absent. Only the two token-backed ChatGPT modes expose this locally verified account; other modes remain unavailable to this reader. This completes the selected-identity rule without changing historical identity schema or invoking real authentication.
