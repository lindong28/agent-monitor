# Normalize retained source-observation paths

Accepted for implementation on 2026-10-28 after one independent decision review. This is an internal representation change under the existing [incremental collection decision](20261028-4424-incremental-collection.md): retain complete observations and accounting semantics while reducing repeated source-path storage.

Store each active observation source once in `source_files_v2`, assigning an internal integer `file_id`. Store observations in `file_observations_v2` with primary key `(file_id, position)` and a dedup-key lookup index. The observation table uses `WITHOUT ROWID`; every original payload and position remains independent. Source IDs do not decide precedence: replay joins the original path and continues sorting by Python `Path` components and observation position. A source dictionary row disappears when its observations are removed. Retained raw usage is never deleted by source-cache cleanup.

Keep the original four-column `file_observations` table and its index so old code can still execute its existing SQL. New code leaves that table empty after successful reconciliation. Triggers record old-table INSERT, UPDATE and DELETE paths in `legacy_observation_paths_v2`. New collection reparses sources with an old or NULL signature or a queued legacy mutation; unchanged v2 sources remain cache hits. Disappeared sources are the union of parsed-cache paths, dictionary paths and queued paths minus current active paths. Including queue-only paths covers a source introduced and removed entirely during a downgrade. Clear each handled path's legacy rows and queue entry in the same transaction, preserving retained raw facts.

The first migration copies exact old observation rows into the new representation in the existing archive write transaction. Only after the copy does it promote the exact `observations-v1:` signature prefix to `observations-v2:`, preserving the full parser/source fingerprint suffix. NULL and older opaque signatures still retry. On subsequent upgrades, old signatures trigger reparse rather than promotion. The migration, raw changes, session metadata and optional preparation callback share the transaction; a callback failure rolls back the migration as well. The old raw dirty/pending triggers remain active across code rollback.

An in-place old-table schema change would break older writers. A compatibility view would also have to support their table/index initialization and write operations. Permanent dual writes preserve the duplicated storage cost. VACUUM alone cannot remove the repeated representation and remains a separate explicit maintenance action. Event-key or payload coalescing is outside this change because differing observations with the same key are needed for completion, conflict diagnostics and source replacement.

A consistent local archive copy measured on 2026-10-28 contained 165,932 observations across 3,052 paths. The original observation table and its two indexes occupied 230,572,032 bytes. After migration, the new observation table, lookup index, path dictionary and index, empty compatibility table and indexes, and legacy queue and index occupied 149,938,176 bytes: 80,633,856 fewer active bytes (about 35%). All reconstructed `(path, position, dedup_key, entry)` rows matched, and hashes of eight existing raw/session/accounting/diagnostic tables were unchanged. This measurement isolates the path migration; it does not include the separate model-count/index initialization.

On that single copy, migration used about 0.366 CPU seconds and 0.431 wall seconds. The file itself grew from 1,195,122,688 to 1,257,943,040 bytes while old and new structures coexisted; afterward its freelist rose from 21,266 to 56,289 pages. No VACUUM was run. The active-page reduction is therefore not a claim that filesystem space was released, and the one-copy timing is not a production performance guarantee.

Verification covers exact migration without source reparsing, NULL/opaque cache retries, opposite file-ID/path ordering, same-file duplicates, old-write queue invalidation and disappearance, empty/erroring sources, transaction rollback, and unchanged rounds with no event decoding or observation scans at two synthetic history sizes. Frozen actual writers from `d535619` and pre-incremental `2b983496` passed old/new round trips, including old writes followed by source removal. Codex and Claude observations matched the v1 writer over 100 synthetic rounds each. These are isolated archive and consumer tests; deployment and live collection remain separate acceptance steps.
