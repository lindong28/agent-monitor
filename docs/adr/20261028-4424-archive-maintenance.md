# Explicit archive physical maintenance

Date: 2026-10-28. Scope: the retained usage archive, without changing accounting or historical retention. This implements the independently reviewed maintenance decision; it does not enable a periodic job.

`agent-monitor archive` (or `archive stats`) reports storage using read-only SQL. It does not initialize missing archives, check integrity, or assert consumer correctness. `agent-monitor archive compact --backup /persistent/new-file.sqlite3` explicitly creates a new recovery copy and compacts the existing archive in place. `--archive` selects an existing `usage_archive.sqlite3`; optional `--rollup-db` must resolve to `rollup.db` in the same directory. The default paths use this checkout's existing state directory, including its symlink. No state directory or lock is replaced. Existing `rollup.db` and its initialized lock are required for compact.

Compact acquires the same `rollup_lock` as cooperative writers, opens the source with mode=rw, creates a private mode-0700 working directory under the backup parent, reserves its mode-0600 snapshot file while retaining its descriptor, uses SQLite Connection.backup, verifies that same object with quick_check and descriptor/path identity checks, and syncs it and the directories. Only then does an atomic non-overwriting hardlink publish the requested backup name. SQLite never opens the caller-visible backup destination for writing. Both links are retained as one physical recovery file; manage their retention together. The verified inode/size/mtime is checked again before VACUUM and before returning; replacement of the published path is a failure with the actual private work path retained in the report. Existing targets, dangling symlinks and existing backup sidecars are refused. Live archive/rollup sidecar paths cannot be used as backup targets. The source inode is not replaced. WAL mode receives an explicit TRUNCATE checkpoint after VACUUM; a blocked checkpoint is a failure, not a claim of physical recovery. Source quick_check follows; application-level verification remains a separate acceptance task.

The dedicated CLI configures SQLITE_TMPDIR before its first SQLite connection, checks write/search access to the archive directory, and explicitly uses the standard Unix VFS on macOS/Linux. This environment change is confined to the CLI process; do not call its main inside the service. The logical budget size is max(main file bytes, page_count × page_size), so WAL-only pages are not omitted. The source volume requires twice that size in extra free space; the backup requires once that size. Same-volume requirements are added before backup, and source free space is checked again before VACUUM. WAL bytes are reported separately. These are conservative preflight checks, not a reservation against unrelated disk writers.

`--budget-seconds` defaults to 300 and covers lock wait, backup, validation and compaction cooperatively. Backup and SQLite VM progress callbacks stop work at expiry; individual filesystem and synchronization calls may exceed the budget. There is no automatic retry or recovery overwrite. Failure reports the stage, whether VACUUM was attempted/completed, and whether the retained backup was verified. Unverified/partial backups remain available for investigation and are never called recovery-ready. Resolve the cause, inspect live data and any retained backup, and choose a new backup path before retrying; never restore an old snapshot over newer writes automatically.

Human output is the default; `--json` opts into structured observations. A failed operation returns nonzero. Reports distinguish archive main-file reduction, archive plus WAL reduction, and retained backup bytes; none is represented as whole-machine net reclaimed space. Backups represent the snapshot completion point and may exclude later commits. No backup expiry is introduced; the operator retains or removes recovery copies under the relevant retention authorization.

Validation uses isolated synthetic archives, explicit archive/rollup paths and fixture working directories, without overriding HOME, with real public CLI execution, real backup/VACUUM, native UsageArchive reads before and after, lock contention, failure injection, WAL logical-size accounting and interrupted VACUUM. `tests/test_archive_maintenance.py` is the repeatable entry. It retains fixtures below AGENT_MONITOR_TEST_ARTIFACTS, or ~/task-artifacts/agent-monitor-tests, for manual inspection/cleanup. No provider request or production archive is involved. See the task implementation report for exact run evidence; tests do not establish power-loss durability or production-scale latency.

References: [SQLite VACUUM](https://www.sqlite.org/lang_vacuum.html), [temporary-file directory selection](https://www.sqlite.org/tempfiles.html), and [incremental collection](20261028-4424-incremental-collection.md). The source-control change contains no deployment or production compaction receipt.
