# Root commands and resource owners

Status: accepted, 2026-10-30. Supersedes the root-adapter, bootstrap and configuration placement clauses of [package entrypoints](20261028-9e4b-package-entrypoints.md). Its domain ownership, state, identity, accounting and provider constraints remain in force. The user approved the root comparison recommendations and their implementation; independent decision review approved this scope after clarifying configuration rollback.

Use agent-monitor for routine operations, including deployment, scoped service status and provider hold controls. Migrate the redundant start/stop/status/deploy/upstream-controls adapters and document their replacement commands. Keep runtime_rebuild.py as an independent external-interpreter rescue entry, along with installation, uninstallation and ip-check. Internal service dispatch executes pinned package modules in separate processes, preserving the caller cwd/environment and the external interpreter during runtime replacement.

Place checkout paths in agent_monitor/paths.py and bundled fallback prices beside accounting/pricing_fetcher.py. Keep token_cost.py byte-identical at its cross-project contract path. Operator defaults and new overrides belong under config/. Existing root *.local.json overrides remain readable during migration; simultaneous old/new overrides are an explicit conflict, including broken links. Do not move or overwrite private configurations automatically. The same selected configuration feeds consumers, retirement writes and source identity checks.

A map alone retains avoidable root backcalls and scattered internal resources; permanent redundant wrappers keep competing public entrypoints. A blanket src/apps/packages migration would add packaging and deployment changes unrelated to these maintenance tasks. AIHOT supplies the principle of explicit ownership and a small operation surface, not a mandatory monorepo template. Existing parsers, ip_check, proxy_runtime and web owners remain independent.

Rollback after adopting config/*.local.json requires a stopped-service maintenance window: preserve the selected private configuration, restore its effective contents or valid link at the legacy root location without overwriting an existing destination, then revert source and restart to verify identity. Relative symlinks must retain their target after relocation, or stay at the legacy location. Installs still using legacy overrides need no configuration move. Source revert alone does not guarantee identity preservation after migration.

Acceptance covers actual CLI dispatch, foreign cwd and interpreter selection, configuration defaults/legacy/new/conflicts, invalid links, state identity and source resource coverage, isolated installer/deployment fixtures and independent root-layout inspection. Unknown external users of retired command names need the published migration table; repository searches cannot prove their absence. No production or provider verification is implied by this decision.
