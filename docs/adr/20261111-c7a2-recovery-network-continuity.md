# Preserve quota task network context through recovery

Accepted on 2026-11-11 after one independent L1 review and targeted correction review. The operator approved repairing the preceding quota-task analysis and completing acceptance. This locally supersedes the owner-route-only description for Monitor account recovery in [explicit authentication recovery](20261106-7c21-explicit-auth-recovery.md); [existing source recovery](20261110-01a1-native-auth-recovery.md) retains its account-owning-machine route.

A quota batch uses the paired device network, whereas its failed account recovery previously selected the owning machine network. The inspected batch and recovery state identified different devices. That explains a route-selection difference but does not establish actual business-request public IPs or the cause of a saved HTTP 401/token_expired.

Retain safe device and anonymous-preview context on each original quota operation. Legacy operations may recover their device only from a matching batch; missing evidence remains unknown. The account recovery status and shared confirmation carry the original operation, current pause and selected device. Preserve the original connection by default; a new connection or missing history requires explicit explanation and confirmation in the same existing dialog. Connection IDs identify ephemeral registrations, not persistent physical devices. Never silently fall back to the owner route or require a paused account to repeat a query merely to establish a network context. Validate and save the chosen context under the original account/pause locks before executing. Both authentication refresh and asynchronous device reauthorization use the confirmed network while credentials remain on their owning machine.

Bind confirmation to current bridge generation and the previewed business/authentication origins actual route keys. Configuration generation alone cannot detect PAC results or fallback changes within a generation. The bridge must reject unconfirmed routes at resolution, connection and handshake boundaries; other official dynamic origins retain existing resolution with generation checks, without claiming target-specific preview coverage. Preview cache reuse requires corresponding generation and route evidence; a changed route cannot turn a cached observation into current evidence or bypass the existing probe cooldown. No extra public probe is added to each quota request. This cannot pin or prove the public IP behind an unchanged external proxy.

Alternatives rejected: passing connection only in the frontend leaves the backend fallback intact; route ID alone misses configuration and PAC changes; forcing all operations through the owner route changes the approved user task. Reuse the shared preview and single-use approval rather than introducing another approval system. Preserve automatic admission, native/configured recovery, identity validation, pause leases, child deadlines and no-replay behavior.

Recovery is complete only after a same-account valid quota observation is saved and published to normal consumers, the original operation/batch reflects success and its matching pause is released. Preserve previous failure and bounded preview/connection evidence separately. Returning to the batch does not automatically dispatch any request.

Acceptance uses isolated fabricated accounts, controlled proxy/origin traffic and the real browser modules. It must distinguish original device continuity, explicit connection replacement, stale pause/task rejection, configuration and same-generation route changes, disconnect without fallback, old missing context, and original batch readback. Real provider restoration and the earlier public exits remain separately unverified; general development/deployment permission does not replace the existing per-action upstream confirmation.
