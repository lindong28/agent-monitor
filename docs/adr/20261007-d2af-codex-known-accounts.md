# Codex batches use the known account directory

Status: accepted 2026-10-07 after one independent decision review. Supersedes only the manually added membership requirement in [b923](20261007-b923-codex-account-batches.md), following the user's explicit correction that previously logged-in accounts must appear without additional adding.

Use current admitted Codex metadata and historical account memory as the candidate directory. Read the existing sources without refreshing providers or upserting memory. Deduplicate by workspace ID and case-insensitive email, preserving distinct workspaces and distinct members of one workspace. Automatically create/reuse private action profiles; profiles cache credentials and results, not membership. Missing email identities are explicitly reported and excluded from the actionable count. Missing memory is a normal empty history; unreadable memory is a visible directory failure, not permission to claim complete coverage from a partial list.

Remove the email-add form. The quota-row action locates the corresponding automatic card. GET never authorizes or sends. An explicit batch click sends to the current directory; the manifest remains fixed after publication. Next rounds and explicit retries exclude identities removed from the current directory. Old manifest members retain their visible results and are marked outside the current directory. Cancellation and credential clearing remain available even when discovery fails. Existing isolated credentials are reused, but metadata is not a credential: missing credentials require official authorization. Do not import remote or ordinary CLI credentials.

Browser-side add loops were rejected because they retain a separate membership workflow and request races. Importing machine credentials is unnecessary to remove the manual account-add step. Keeping manually managed membership contradicts the new request. Existing fixed-message, identity checks, persistence and no-blind-resend rules remain unchanged.

Known boundary: the account-memory resurrection race documented in [general issues](../issues/general.md) can make a removed identity reappear, and therefore enter a later explicitly requested batch. This change does not promise permanent exclusion or rewrite account-memory semantics. It can discover only accounts recorded by agent-monitor. Real authorization, inference and provider reset behavior are not established by synthetic tests.

Verify zero manual additions through the real HTTP handler with current/history metadata, duplicate machines, multiple workspaces/members, removed identities, source failures and actual synthetic send counts. The decision review returned all seven criteria成立; the removal and unreadable-source weaknesses were resolved before implementation.

Local validation: 55 account tests and 39 Web static tests passed. Five new HTTP tests use real directory/handler/manager code with isolated current/history metadata and synthetic stdio, covering four distinct workspace/member identities, duplicate machines, missing/valid/corrupt history, missing email, removal, duplicate requests and send counts. The change reviewer found that reusing the quota projection silently excluded identities with no quota timestamp; discovery now reads admitted identity blocks directly, with valid/null/missing/invalid timestamp regression coverage. An isolated headless browser showed three discovered identities without an add form; one click produced two completed messages and one authorization wait. Reload retained the batch, and the quota-row action focused the matching workspace card. A 390×844 observation showed no document horizontal overflow. Real accounts and provider reset behavior were not exercised.
