# Local dashboard with local network observations and Hub statistics

Accepted 2026-10-31 after independent L1 review of the v2 candidate. Extends [process observations](20261030-4c42-process-network.md) and [capability composition](20261031-4c42-capability-network.md), superseding their popup-only normal entry and closure-only browser retention. Their account ownership, explicit probe permission and evidence boundaries remain.

The normal `agent-monitor open` entry uses the existing local HTTP service and overview. A configured Hub client reads statistics through a fixed-origin GET allowlist, including session details, with `sync=0`, no `force`, redirects or forwarded credentials. Hub failures remain Hub failures, never a silent switch to local statistics. Local health and network identity remain local; statistics timezone and operating-system network timezone have separate sources. Existing Hub account management, pairing, refresh, quota recovery and remembered-account removal remain at the Hub origin, reached by explicit links from the local interface.

The existing network page automatically reads local passive host/process facts when reached through loopback. Its API checks both TCP peer and Host/Origin, rejects cross-site requests, and requires the application header. Host addresses, DNS, timezone and redacted proxy configuration remain useful without a running or selected Agent. Reading or revisiting does not contact public diagnostic services. Optional third-party and fixed-provider diagnostics retain route/instance revalidation and separate explicit actions. Reports and sanitized receipts retained by this browser are dated history, never fresh evidence or portable probe authorization.

Remote network URLs keep the existing manual connector popup path and explain how to open the local installation. Server diagnostics retain their own subject; a cached-only read cannot initiate an expired diagnostic. The connector continues to own Hub account transport. No second daemon, private helper dependency, usage-schema migration or identity replacement is introduced.

Alternatives considered were automatic remote popups (still dependent on popup/Hub registration), a second UI in the connector (duplicate lifecycle), explicit Hub statistics navigation alone (loses existing same-origin aggregate consumers), and an unrestricted API proxy (changes account trust). The narrow read adapter preserves existing aggregate pages while keeping action ownership explicit.

This decision supports the local network task and existing configured Hub use; it does not claim arbitrary proxy compatibility or automatic probe consent. At decision time implementation, isolated installation/update, entry/revisit/failure observations and two-host deployment acceptance were still unverified. Those results belong to the task evidence and public usage boundaries, not this decision.
