# Bounded diagnostic reread inside an admitted quota-only operation

Accepted 2026-11-11 after independent L1 review and targeted resolution of the authentication-source conditions. The user approved bounded automatic recovery under verified identity, route, permission and budget, rather than requiring manual investigation for every internal error. This adds a narrow exception to the normal single-RPC policy in [credential refusal handling](20261110-c3a5-quota-credential-refusals.md) and [recurrence](20261106-quota-recurrence.md); it does not reinterpret all -32603 errors as transient.

An ordinary quota-only operation may consume one additional quota RPC after the fixed official-client usage transport failure, on the same app-server, identity, credential generation, provider lease, bridge and total deadline. Only audited 0.166/0.167 client versions, standard file OAuth, an unchanged access-token digest captured before child startup, and a parseable access-token expiry beyond the client's five-minute refresh window plus the remaining deadline qualify. Unknown data, versions, expiry, authentication refusals, rate limits, invalid results and changed identities do not qualify. Recovery, login, sending and post-send quota reads retain their existing budgets. Existing pauses are never cleared or probed automatically. A consumed opportunity cannot restart through a new pause ID, scheduler tick or process restart.

Native quota children explicitly select the original file credential store, matching the auth.json already used for account identification and generation checks; retain HOME, CODEX_HOME, user/system configuration and the Monitor bridge, and exclude alternate authentication environment inputs. Do not add a forced-login-method constraint. Managed children retain their existing file/ChatGPT isolation. Config/read reloads configuration and is not used to infer the startup AuthManager's source. File JWT expiry is a client refresh-policy input, not proof of upstream authentication.

Retain a bounded, redacted RPC message/data text projection with truncation flags through the existing diagnostics and failure records. The diagnostic projection is not admission authority. Retain the first failure and finite reread outcome through existing operation, quota and provider-control records; a valid current same-account observation must still reach its normal persistence/consumer path. After the budget fails, keep the original protection and maintenance diagnosis; no background replay or fictitious support assignment is added. Keep a bounded latest reread receipt, not an unbounded incident log.

Official app-server documentation identifies account/rateLimits/read as the quota reader but does not establish -32603 transience. Current 0.167 loopback tests observed one usage and one reset-credit GET per tested RPC, additional account checks, and proactive OAuth for an expiring token; these are received mock HTTP counts, not a universal network-attempt bound. The budget is at most two Monitor quota RPC opportunities within the existing total deadline, not two HTTP requests. Preserved source and evidence are under ~/task-artifacts/agent-monitor/20261111-internal-error-closure-01a1ca00/.

Implementation and deployment acceptance remain separate. Before changes, the owning-machine status read reported macbook unpaused, no active operation and a successful last recovery; this neither identifies the original transport cause nor authorizes an extra live provider request. Local fault injection, original protection counterexamples, restart/concurrency and actual dashboard consumption must validate the final change; no real-provider or future-version guarantee follows from synthetic results.

Local acceptance used synthetic native and managed stdio peers, including transient/persistent errors, unknown data/version/expiry, changed credential/identity, a fixed deadline and held provider lease, cancellation, and restart/old-pause exclusion. The identity-change evidence-loss case failed before its fix and passed afterward. Dashboard fixtures displayed a successful reread in observation details, a consumed unsuccessful opportunity in account maintenance, and unknown error.data as a redacted text projection. These do not establish a real provider retry or the historical root cause. Independent implementation review found one diagnostic-loss defect, fixed with its targeted regression; no independent baseline finding remained.
