# Commit an already obtained Monitor quota observation

Accepted after one independent L1 review, with all seven criteria accepted. The real device authorization and quota verification succeeded, but their candidate could not be committed: the Monitor-owned profile was absent from the native collector's cache and published membership. Tests had prepopulated both. A Monitor account registered from the historical identity directory is a distinct source from a portable codex-account profile; neither another machine's identity nor a fabricated collector entry can establish its ownership.

Admit an explicitly obtained observation for an existing local Monitor profile by its registered profile, workspace and email. Reuse that metadata check for the cache writer, owning-machine publication and subsequent quota-view merge. Keep native and remote admission unchanged. This does not enroll Monitor profiles in automatic queries, change discovery, or copy credentials. Preserve the existing permission fields when converting the observation. Profile deletion or identity change invalidates the added local admission.

Bind it to the current operation, local-commit pause and its source, original recovery chain and current local identity. Recheck restrictions and the current quota window under the existing profile and provider locks. Reuse the existing commit/publication compensation; do not initialize a client, authenticate, probe egress or query quota. Preserve the old failure chain and current pause diagnostics, restore the original quota operation only after saving, and clear only the matching pause. A failed local continuation removes only its own newly created local probe marker and retains the candidate, so another repair does not require upstream work.

Capture existing bridge connection observations before closing the recovery client, so a later local failure does not lose its available network evidence. This reads the local helper only. Earlier missing observations and the human authorization browser's unverified egress remain unknown; neither is reconstructed by sending another request.

Alternatives were extending collector discovery (changes enrollment and query work), mapping to another machine's profile (changes ownership), writing only the cache (publication and merge still reject it), or a separate results store/page (duplicates existing consumers). The selected path preserves the separate collections and full identity rules in the earlier quota and recovery decisions. Persistent state remains the existing locked JSON records and latest quota publications; no schema version, daemon, database or retention expansion is needed. Existing bounded compensation is retained, without claiming atomic recovery at every power-loss point.

Acceptance covers missing and existing cache/publication membership, identity change/deletion, permission projection, expired candidates, wrong operation/pause, failed local saves and repeated submissions. The shared Manager, publisher and QuotaView must consume a first observation without fixture-seeded membership. The real continuation must issue zero provider requests and restore the original task and normal account view from the already saved candidate. The real authorization/quota budget has already been consumed; product repair is not permission to repeat it.

The normal quota-view merge also consumes subsequent explicit local Monitor observations from the same quota cache. Admission requires the registered full identity and the same active observation timestamp in the profile's retained quota. Operations carrying a recovery chain continue through the transactional publisher instead, so a failed recovery candidate cannot leak through this cache path. Unreadable local cache retains published observations and exposes the existing cache-error status. This closes the ordinary-refresh continuation without enrolling the profile in collector queries or adding another publisher or store.

The local addition also requires the admitted generation to identify the currently running physical host. An existing publication with a mismatched host identity or machine endpoint cannot be bypassed by the local cache. The same verification gates local Monitor publication membership, while remote/native rows keep their existing admission path. Identity lookup failures retain the source restriction and existing diagnostic surface; no network fallback is attempted.
