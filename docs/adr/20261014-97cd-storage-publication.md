# Read mutable SQLite under ownership and publish fresh automatic imports

Date: 2026-10-14. Status: accepted after independent decision review. Scope: the user's ten-object contract repair request; local implementation and production verification remain separate.

An absence-of-WAL sample cannot establish SQLite immutable's lifetime premise, and a FULL checkpoint need not truncate the WAL. Keep normal read-only access; when a mutable diagnostic/fallback needs a stable view, use the existing cooperating rollup lock to copy DB and WAL to a private directory, recover that private copy, close the recovery connection, and read the now-stable copy. Leased published generations remain explicitly immutable. Do not treat nonzero WAL size as proof of pending frames, switch system Python solely because its SQLite version appears in the affected range, or weaken ownership by reading mutable files as immutable. The audited project-owned writers and connection closes already share the lock; external producers do not inherit that guarantee.

Sample published_at during the short commit phase after long preparation and lock acquisition. Preserve the existing pending/current/previous crash-recovery sequence. Automatic bundle installation must reject generated_at older than validated current while holding the publication lock, including legacy bundles; same-time imports retain existing identity/retention checks. Direct publish remains an explicit recovery mechanism. This distinguishes ordinary freshness from deliberate restoration without imposing a new signed anti-replay protocol or hardware power-loss promise. A regressed source clock now refuses automatic replacement and preserves current.

Remote export needs a lifetime owner independent of the local SSH client's timeout. Use a one-shot supervisor and a session-leading guardian, a parent-lifetime pipe, and an inherited same-open-file-description directory lease. Cleanup and age reaping require a nonblocking exclusive lease and inode recheck; retain legacy directories without lease. If guardian dies first, live export still holds the lease, preventing directory deletion; this does not claim a dead guardian can enforce its deadline. Ordinary supervisor death/deadline triggers group cleanup while the leader still reserves identity. Do not kill a group after its leader has been reaped. This does not contain arbitrary setsid descendants or unschedulable interpreters.

Alternatives rejected: two WAL-stat samples, treating every nonempty WAL as an error, blanket runtime replacement without a reachable race, banning explicit restore, age-only remote deletion, or assuming killing SSH terminates remote work.
