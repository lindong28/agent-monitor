# Nominal geography compatibility and focused cost diagnostics

Date: 2026-10-18. Status: accepted after one independent decision review for diagnostic presentation and one for the pricing increment.

The user requested fixing unsupported service-mode valuation, removing repetitive pricing coverage from Overview/Explore, and concentrating incomplete usage and unknown-model diagnostics in Collection. The user subsequently explicitly allowed existing collection to update recent historical estimates; no additional history replay is authorized by this change. Token population, source records and subtotal/null/known-zero meanings remain unchanged.

Accept `not_available` only for Claude nominal valuation, retaining its source value and using geography multiplier 1. The official usage-report documentation defines this sentinel for models without geographic routing; that alone does not establish newer-model pricing. The independent stronger anchor is Claude Code 2.1.296 SHA256 `c9b5341637becbd423ddffc5b254afb645682a3868cb708bbc6cc0e7bb419937`, byte 189651120: `rM` returns 1.1 for `us`, otherwise 1. `Flt` multiplies the nominal token amount by it; `PSe` uses that path outside custom organization prices. Extracted function outputs for `us`, `global`, `not_available` are 1.1, 1, 1. Source samples also contain the sentinel on newer models. This is bounded client nominal valuation evidence, not actual-region, final-usage or invoice evidence. Unlike the client fallback, Monitor still rejects arbitrary unsupported values and preserves all existing price/quality gates. Sources: [usage report](https://platform.claude.com/docs/en/api/beta/organization/usage_report/retrieve_messages), [data residency](https://platform.claude.com/docs/en/build-with-claude/data-residency).

Overview/Explore explain the shared scope once and retain subtotal labels. Repeated coverage counters move to retained-detail diagnostics; the optional aggregate unknown-cost metric remains available. This supersedes the repeated display requirement of a7c2, not its cost population or arithmetic. The 58e1 evidence semantics and 9e31 drilldown capability remain.

The new diagnostic endpoint groups unknown amounts by machine, agent, model and reason. Hub mode reads recorded reasons from admitted snapshots, retaining an unrecorded category for old evidence. Standalone mode intentionally follows the existing Sessions loader: local source parsing and current-price estimation (including possible price fetching), without persisting usage. Its reasons describe the current estimate rather than stored historical evidence. It supports Hub and standalone, exact date/model/agent/machine filters and canonical project aliases. Source-context links preserve filters and return navigation; each group opens all unknown records for that machine/model, not an exact reason-only filter. The existing status endpoint remains inexpensive; cost diagnostics is read on entry/manual action and not periodic polling. Legacy rollups can outlive retained detail, so counts may differ. Prefer this to N per-session detail reads or a recurring scan. No persistence/schema migration is introduced.

Implementation acceptance covers no-geo versus US valuation, unsupported values, incomplete usage and recorded-amount precedence; diagnostic record counts versus event weights, known zero, empty scopes, source filters and drilldown/return.
