# Load requests before optional full-range analysis

Status: accepted for local implementation, 2026-10-08. The user selected “请求优先，附加功能按需加载”. One independent decision review and a targeted clarification passed. Publication and deployment require separate authorization.

Partially supersedes d83e and UX H2 only for loading order: the first screen reads a request page, while exact totals, outcome statistics, cost subtotals, independent attempts and complete filter choices load on explicit action. Keep all filters, request detail, both pagers and full export. Unloaded aggregates are not zero or page totals. Full analysis replaces the entire displayed observation; later lightweight refreshes clear its aggregates rather than combine snapshots.

Add a monitor-owned read-only list adapter over admitted snapshots, selecting request candidates and their complete attempt chains before Gateway projection. Reuse Gateway validation, row projection, filter, ordering and cursor semantics without modifying its separately owned checkout. Validate active selections against the existing range option authority before projecting calls, including parents outside the request window with children inside the attempt window. Return verified active options; complete options remain on demand.

Create optional time-expression indexes during export before digest binding, leaving versioned tables and payloads unchanged. Already published generations stay read-only and work without the index. SQLite time buckets only narrow candidates: consume entire boundary buckets and use Python's exact timestamp ordering. Timestamps SQLite cannot parse take a Python fallback and participate in the same merge. Sparse attempt filters and large time buckets may still scan many rows; batching is not a result truncation limit.

The baseline live page took 38.195s and a concurrent page request 75.504s. On one frozen source with 369,775 requests and 369,825 attempts, an instrumented call took 32.284s: observation loading 23.161s, filter projection 2.388s, calls projection 5.474s, finally returning 50 requests and 50 attempts. These profiler timings establish stage costs, not production latency predictions. Hiding sections alone leaves the full decode; full-observation caching retains cold-generation cost and large heaps; adapting Gateway's own ledger index would expand the ownership and schema surface.

Scope: Hub snapshot list performance. Standalone retains its existing reader, with no standalone performance claim. Source identity, coverage, retention, monetary arithmetic, request-time/attempt-time semantics and existing full APIs are preserved. Known unverified items at decision time: exact SQL/Python boundary parity, multi-machine pagination and filtering, stale UI responses, and real browser first-page performance. Rollback is a local code revert, with no historical data rewrite.

Local implementation validation subsequently covered those boundary cases in isolated fixtures and exercised the real browser against a frozen source copy. Review corrected an unusual-offset cursor and an early-analysis selection race. Detailed measurements, remaining cold/production gaps and the unchanged full-analysis cost are recorded in [operations](../operations/services.md#2026-10-08-request-first-list-local-validation). This evidence does not authorize or establish deployment.
