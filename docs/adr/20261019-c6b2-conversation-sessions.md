# Present retained usage as user conversations

Accepted 2026-10-19 after one independent decision review (seven criteria passed). The owner approved grouping native Codex subagents under their main conversation, simpler session views, matching list/detail scope, and useful partial cost sums. This supersedes the strict Sessions amount in 20261014-a7c2 and the default full-retained detail scope in 20261007-e781; their other navigation, source and evidence constraints remain.

Store one session metadata record separately from usage events in the existing SQLite archive and publish it in statistics extension v4. Keep v1–v3 readable. Native Codex source parent IDs are the relationship authority; recursively group only complete, unambiguous ancestry on the same machine and agent. Ordinary forks, wrapper processes and directory/time resemblance do not establish membership. Missing, conflicting or cyclic ancestry remains independently visible. Original usage keys, inherited-history exclusion and pricing arithmetic are unchanged. Use existing Codex names/titles and source creation times; Claude and unavailable metadata use directory/time fallback. No transcript extraction or generated summaries.

Build ancestry before event filtering. Sum only matching facts within each group; detail uses the same date and filters by default and provides an explicit all-retained switch. Display latest observed usage, not inferred running/completion status. Preserve observed span as a secondary value, distinct from source creation. Known costs sum even with unpriced members, with a visible qualification; unknown-only remains unknown and known zero stays zero. Source execution IDs and per-record model/pricing evidence remain available through disclosure.

Rejected alternatives: repeating metadata on every UsageEntry inflates events and cannot express a parent without usage; browser-only grouping loses ancestors outside the filter; request-time source-log access couples page latency and availability to remote sources. SQLite retains its existing single collector/transaction and immutable admitted snapshot roles. Metadata grows by session, follows archive retention and is not a new transcript store.

Deploy a compatible Hub reader before v4 source exporters. After v4 publication, code rollback must retain that reader or use a compatible forward fix; reverting to the old binary is not a data-compatible rollback. No extra historical cost replay is part of this work. Existing event retention guards continue; metadata retention is checked too.

Evidence: the baseline pipeline at 9e9d899 groups by execution ID and has no parent carrier. A local header-only sample contains 1044 unique owner IDs across 1494 physical files; all 845 native parent references match owner IDs, not filename-derived guesses. This is a bounded local observation, not universal producer coverage. Decision report: `/Users/lindong/task-artifacts/conversation-sessions-20261019/decision-review.md`.
