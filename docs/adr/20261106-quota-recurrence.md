They verify credential identity before startup and around the query, response identity and usable windows. Login and sending keep the remote account check.

The error interpreter retains existing precise-message explanatory mappings, but unknown errors now retain safe diagnostic context. Diagnostics reuse bounded operation/last_failure and shared pause records and their existing readers, locks and lifecycle. No unbounded error log, new database or alert service is introduced. Query failures already surface in the active operation and collection outcome; the failure and recovery identities remain unchanged. Tests use isolated homes and stdio peers, including ordinary-entry recurrence, unknown errors, changed credentials, missing windows, old-pause admission and post-send failure. Real provider restoration is a separate, specifically approved verification; an alternate-path success alone does not close normal-entry acceptance.
