# Indexed session reads and bounded runtime diagnostics

Accepted 2026-10-13. Decision review: one independent reviewer, two narrow corrections verified; seven criteria pass. Scope and baseline evidence: [performance record](../performance-20261013.md).

Keep session predicates, position ordering, complete detail and current generation admission. Add optional timestamp-date and session-id expression indexes only to unpublished exported copies. Old snapshots remain readable; rows, snapshot versions, arithmetic, retention and update cadence are unchanged.

Add bounded in-process HTTP/background-operation observation and a read-only diagnostics endpoint. An independent observer in the Hub lifecycle persists current state and rotating events; it does not take query preparation/sync locks. Track completed and still-running operations, known source observation times, evidence gaps and persistence failures. Bound active details, recent completions and pending events to 256 each and report drops/partial coverage. Use configured collection interval for age_intervals, not an inferred count of missed rounds. One-second slow and thirty-second long-running markers are diagnostic thresholds, not SLA failures or cancellation rules. Preserve the existing six-hour stale definition.

Alternatives were request caching (first-read and invalidation/memory costs), a new aggregation store (larger accounting semantic change), completion-only logs (cannot reveal hanging work), or a new monitoring service (unnecessary deployment dependency). This implementation preserves the existing shared-state and provider boundaries. Index construction cost and observer overhead require measurement before release. Operators consume /api/diagnostics and state/diagnostics files to initiate targeted performance audit; whole-process death/freeze needs an external observer and remains assigned to the Monitor deployment maintainer. External notifications are not enabled by this decision.
