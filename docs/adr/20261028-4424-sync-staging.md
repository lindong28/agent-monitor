# Reclaim owned local sync staging after its users finish

Accepted for implementation on 2026-10-28 after one independent decision review. This decision covers local sync staging only. It does not change historical observations, generations, incremental state, remote temporary directories, or service-log retention.

`sync_machine` previously relied on `TemporaryDirectory` cleanup, which does not run after process termination. Use a local staging protocol under the existing state parent: a persistent registry lock serializes initialization and reclamation, each new directory has a locked lease, and the owner marker binds the protocol to that lease's device and inode. Publish the marker only after acquiring the lease. The existing state-root symlink remains supported; candidate directories and their ownership files must not be symlinks. Reclamation uses descriptor-relative traversal without following payload links. Delete the payload before ownership metadata, so interruption during large deletion remains retryable.

The sync owner keeps its lease during export and admission. Local rsync transfer additionally runs under a short-lived transfer owner, with the lease passed to both processes. Publish an in-flight intent before spawn and clear it only after the actual command exits and its output pipes reach EOF. Parent termination leaves that owner able to finish; owner termination leaves intent behind and prevents reclamation even when an executable closes extra descriptors. The owner bounds normal transfers with the existing remaining budget and terminates its owned process group on timeout. The caller retains the original deadline. An owner killed before completing this protocol cannot certify its descendants' lifetime: preserve the directory and report the unfinished-transfer reason, rather than infer safety from PID reuse, elapsed time or unchanged file size.

The ordinary sync entrypoint reaps completed protocol-owned directories before starting new work; no new scheduler or persistent service is installed. Normal context exit uses the same reaper rather than bypassing leases. Unknown versions, legacy unmarked directories, replaced lease identity, busy leases and unresolved transfer intent remain intact. Cleanup errors do not replace the primary sync error. A retained directory may require a separately authorized operator investigation; do not remove its intent merely because its original parent is gone.

Each reclamation call reports exceptional retained directories in one warning, grouped by reason with counts, the state root and at most two directory examples per reason. Missing ownership, unknown protocol and changed identity remain distinguishable. Normally busy leases do not warn. This is bounded per invocation, not a new persistent deduplication or alert service; retained objects are still checked on later sync calls.

Age-based deletion and parent-PID checks cannot distinguish paused or orphaned active transfers. A guardian alone is also insufficient when it dies before a child that closes inherited descriptors. The durable in-flight intent supplies the fail-closed boundary; it is not a guarantee that every abnormal directory will eventually be automatically reclaimed. Injected runners retain their existing synchronous call contract; a failed injected runner cannot supply completion evidence and its intent remains.

Validation targets normal and failed exports, busy leases, parent termination, real local rsync transfer, guardian termination with preserved and deliberately closed extra descriptors, cleanup interruption, publication/reaper contention, legacy/unknown ownership, symlinks and replaced lease identity. Tests use isolated files and identities without SSH or provider calls. Passing a local OS/interpreter/rsync combination does not establish fleet-wide compatibility, production deployment, or the reclaimability of pre-protocol directories. Caller-provided historical occupancy is not a measured saving from this change.
