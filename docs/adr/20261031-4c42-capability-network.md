# Capability-based local network observations

Accepted 2026-10-31 after independent L1 decision review (seven criteria passed, no findings). Extends the [local-process decision](20261030-4c42-process-network.md). The operator explicitly requested capability composition for heterogeneous open-source installations, optional third-party and provider probes, and repair/acceptance of the existing network page.

Keep one process selection and report. Combine basic OS evidence, an optional passive local Mihomo Unix-controller adapter, explicit third-party IP observation and separate fixed-provider-target probing. Environment support, user permission and evidence scope remain separate. No controller or private harness becomes mandatory; no Hub process storage, agent traffic interception, provider-store reads or automatic public requests are added.

The controller association requires current TCP source and inbound tuples and supplied process path, with process/socket rechecks. Chain names are not public exit receipts. Probes use shared admission and fixed targets through the observed process proxy; no retry, redirect, direct fallback or cross-kind fallback. Free ip-api is HTTP/noncommercial, disclosed before use, and X-Rl/X-Ttl plus Retry-After constrain target-wide cooldown across PIDs. Provider trace is only evidence for that target/proxy/time, not all actual agent requests. Old UI/connector compatibility retains provider kind as the default; missing new admission fields keep new UI read-only.

Alternatives: the old full ip-check uses monitor/system routing and conditional reputation queries, so it cannot stand in for a local agent probe. Only provider probing loses useful independent evidence; forcing a controller excludes legitimate environments; a second page/daemon duplicates the existing connector and task. Shared state and account forwarding retain their existing owners.

The UI must preserve full-instance selection and dated results across refresh/failure, identify disappearance, make unmet admission actionable, and separate disclosure from server detection. The public capability table in public-usage.md owns prerequisites, external actions, boundaries and recovery. Decision evidence was recorded before implementation in task 20261031-capability-network-4c42; this durable ADR records that decision, not completed acceptance. Current supported adapters and finite test results do not promise arbitrary proxy/NAT, Windows, all client configurations or future behavior. Live public probes require their specific approval; prior one-shot approval cannot be reused.
