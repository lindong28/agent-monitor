先确认数据来自哪里

agent-monitor 面向个人开发者和多机使用者，汇集用量、会话、配额与诊断信息。金额是记录或估算，不是服务商账单。

首次接入

单机使用

开始前，准备 Python、Git 和 curl，并进入自己的 agent-monitor 代码目录。

  1. 配置 machines.json。如果是新单机安装，只保留自己的本机条目，见下方示例。如果是已有安装，须保留机器身份和退休记录。
  2. 运行 ./install.sh 安装 Monitor。
  3. 运行 agent-monitor start 启动服务。
  4. 运行 agent-monitor refresh 进行首次采集。

macOS 安装器会设置定时采集。Linux 用户需另行配置定时任务。

新单机 machines.json 示例
{
  "machines": [{"name": "local", "ssh_host": "localhost", "self": true}],
  "retired_names": []
}
单机安装与首次采集
./install.sh
agent-monitor start
agent-monitor refresh
多机接入 · Hub 与采集器

Hub 负责拉取快照；采集器独立保存各机数据。

  1. 在自己的 hub.json 中配置机器角色、URL 和 SSH 目标。
  2. 在每台机器的代码目录中运行以下命令。将占位符替换为该机器在配置中的名称。
多机安装 · 替换为配置中的机器名
./install.sh hub <机器名>

完整命令、依赖与已有服务迁移见代码目录中的 README.md 和 docs/operations/services.md。本页只说明与检查状态，不修改配置或登录账号。

从问题找到证据

  • 想知道成本变化：总览展开周期比较，核对两个周期的日期和金额未知的记录数，再进入透视定位目录、模型或机器。
  • 想追溯某组用量：点击透视排行的“查看会话”。列表只计匹配记录；打开详情可看全部留存记录。汇总比明细更完整时，差额不能当成查询错误或零成本。
  • 想挑选账号：在总览按配额窗口和剩余额度排序，同时核对更新时间。历史账号读数不代表当前可用。
  • 页面为空：先检查日期和筛选，再看机器采集状态与采集器版本。连接失败会保留最后成功快照；修复接入后再刷新。

请在可信个人网络使用；账号操作的来源检查不等于用户认证。开源代码与公开运行中的仪表盘是两件事。
