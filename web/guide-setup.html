单机使用

开始前，准备 Python 3.10 或更新版本（含 venv 和 pip）、Git、curl 和 nc，并进入自己的 agent-monitor 代码目录。

使用真实 HOME 会读取本地日志和当前账号状态。打开页面或浏览单机概览时，Monitor 可自动使用已有登录主动查询配额；仅在同意这些读取和请求时继续，否则按 README 使用隔离样例。

  1. 公开候选默认只包含本机。如需修改，复制 examples/machines.json 为 machines.local.json 后编辑。已有安装须从当前配置复制，保留机器身份和退休记录。
  2. 运行 ./install.sh --no-services 安装 Monitor。
  3. 运行 AGENT_MONITOR_BIND=127.0.0.1 ./agent-monitor start 启动仅本机可访问的服务。
  4. 运行 ./agent-monitor open 打开页面，在「会话」中选择日期范围并打开已有会话。
  5. 需要立即追加一轮采集与配额查询时，运行 ./agent-monitor refresh；这可能访问自己的账号和已配置机器。

--no-services 不安装定时任务。需要定时采集时，macOS 可运行默认安装器；Linux 用户需自行配置调度。服务没有客户端身份验证，不应暴露到不可信网络。

新单机 machines.local.json 示例
{
  "machines": [{"name": "local", "ssh_host": "localhost", "self": true}],
  "retired_names": []
}
单机安装与首次查看
./install.sh --no-services
AGENT_MONITOR_BIND=127.0.0.1 ./agent-monitor start
./agent-monitor open

若快照不可读或更新时间未变化，先查看采集详情中的错误，再检查对应配置与连接。

多机接入 · Hub 与采集器

Hub 负责拉取快照；采集器独立保存各机数据。开始前，确认 Hub 能通过 SSH 连接各采集器。

  1. 在 machines.local.json 中配置机器名称与 SSH 目标，在 hub.local.json 中配置 Hub、URL 和采集机器。已有安装须保留机器身份和退休记录。
  2. 在每台机器的代码目录中运行以下命令。将占位符替换为该机器在配置中的名称。
多机安装 · 替换为配置中的机器名
./install.sh hub <机器名>

安装后，进入 Hub 的「采集与诊断」，逐台核对机器名称、纳入状态与数据更新时间。显示旧快照时，按该机器的错误继续排查。

完整命令、无账号示例与服务迁移见代码目录中的 README.md 和 docs/public-usage.md。
